# RSS 模型价值评分：候选与返回协议

AI 信息价值评分的第一步在 `personal-ai-agent-core::feed_value` 提供纯输入准备和严格输出校验。现有日报继续使用关键词规则分数；本步没有模型发送、费用预留、数据库写入、HTTP 或页面入口。模型评分仅是针对显式偏好的建议，不代表事实核验或客观质量判断。

## 候选与分享内容

调用方必须按当前用户从仓储加载完整、有界、同一截点的候选快照。`plan_value_scoring` 复用 `plan_brief` 的用户隔离、UTC 日窗口、偏好规范化、去重、每来源上限和确定性排序，最多重评其选中的 20 条。不会让模型扩大候选范围或恢复被规则排除的条目。空候选或没有显式关键词时返回 None，未来执行器应直接结束，不发送请求、不占模型费用。

模型输入为固定 system 提示和单条 JSON user 消息。JSON 只包含规范化关键词、候选的本次临时编号、标题和摘要。不附加用户 ID、数据库键、订阅标识、来源链接、发布日期、规则分数或未选中的内容。标题/摘要本身仍可能包含 URL 或个人信息，因此未来必须预览实际分享文本并取得分享同意，不能把字段最小化视为去敏。

精确 JSON（含转义）加固定提示限制为 64 KiB，超限整体失败，不静默截断。字节上限不是 token 上限；未来适配器必须对最终请求进行离线计数并复核上下文容量。请求固定 temperature=0、输出硬上限 4096 token。固定提示把所有关键词和内容视为不可信数据；提示本身不能保证抵御注入，执行路径不得赋予模型工具、网络、记忆或其他副作用能力。

`ValueScoringPlan` 字段私有，无 Deserialize/Debug，只能通过校验构造。摘要绑定协议、提示、输出限制、完整规则日报快照及精确分享 JSON。调整未分享但属于原快照的内容也改变摘要，防止预览和执行间静默换入新快照。摘要不是认证签名，计划也不是派发凭据。

## 返回值

严格 JSON 形状：

```json
{"items":[{"id":1,"score":80,"reason":"标题与用户关键词直接相关"}]}
```

必须恰好覆盖所有本次编号，每个一次。score 必须显式出现，取 0–100 整数或 null；null 表示依据不足而放弃评分，不等于零分。reason 必须为非空、无控制字符、最多 240 个 Unicode 字符的文本，无论是否放弃评分都必须提供。整个输出限制为 32 KiB。

拒绝额外字段、重复 JSON 键、未知/重复/缺失编号、字符串或小数分数、越界分数、代码围栏、尾随内容及无效 UTF-8。任一条无效则整批拒绝，不保留部分评分或静默回退。返回按分数降序、null 最后、同分按规则候选顺序排列，不修改原规则分数。返回理由仍是不可信文本，未来 UI 必须以文本展示，不执行 HTML、链接或指令。

## 后续接入

已提供[候选/报价与 API/订阅用量授权仓储](rss-value-reviews.md)。后续需要接入真实连接验证、事务预留、一次领取与发送复核。执行前再次检查所有权、来源是否删除/停用、条目/偏好是否变化及授权期限；不能用现有 RSS GET 授权或规则日报生成授权代替模型分享和付费同意。派发后未知结果不重试、不自动退还占用金额；取消/来源删除应丢弃迟到结果。协议失败与 usage 结算必须分别处理，不能因结果 JSON 无效推断供应商未收费。

之后再接入受限供应商适配器、用户 HTTP 和评分预览/授权/历史页面，最终决定用户显式选择使用规则排序还是模型建议。当前定时日报不会因此新增模型调用。

## 验证

单元测试覆盖用户隔离、停用/删除过滤、候选上限、最小分享字段、注入文字仅作为数据、摘要稳定性及快照变化、精确 JSON 转义尺寸、完整返回覆盖、稳定排序/null 区别、未知字段/重复键/畸形输出拒绝和理由边界。没有请求实际模型或 RSS 服务。
