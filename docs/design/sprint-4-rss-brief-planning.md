# Sprint 4：RSS 规则评分与 Daily Brief 纯规划

## 本步交付

`personal-ai-feeds::brief::plan_brief` 从当前用户的已保存 RSS 条目快照和显式关键词生成日报计划，输出所选原文、分数依据、去重/省略数量和确定性摘要。实现不依赖数据库、HTTP、系统时钟或模型，不增加迁移、费用、自动轮询或通知入口；尚未提供日报保存、API 或页面。

本步的“价值评分”是可解释的规则相关度，不判断事实真假、来源可信度或内容质量，不生成摘要文章。输入中的标题、摘要、链接和发布时间仍是不可信外部资料；指令样式的正文不会被执行或交给模型。

## 输入边界

调用方明确提供 user、request_id、UTC 日起点、as_of 截点、关键词和完整有界候选快照。用户、请求、订阅必须为非空 UUID，统一规范化；每条候选都核对用户，包含随后会被排除的停用、删除或旧条目。输入类型支持内部数据库快照的严格 Serialize/Deserialize，不作为客户端计划的反序列化入口，也不实现包含正文的 Debug。

- 最多 500 条输入，重复行也计入输入数量；所有文本字段的 UTF-8 原始字节合计最多 2 MiB，超过时整体失败，不静默截断。
- 沿用条目标题 512 字、摘要 8192 字、发布时间 256 字、链接 2048 字上限；标题和摘要不能同时为空白。
- 条目键只接受 `guid:` 或 `link:` 加 64 位小写十六进制。链接复用 HTTPS 公网域名语法规范化；此处不解析 DNS，也不承诺地址真实可达。
- 首次保存、内容更新、最近观察时间必须为正且依次不减，最近观察时间不能超过 as_of。来源声明的 published_at 仅保留原文，不参与日期判断。
- 最多 5 个关键词，每个最多 64 个 Unicode 标量且原始字节不超过 256；拒绝控制字符，去首尾空白并转小写，拒绝空词及规范化后重复项。排序后参与计划，输入顺序不影响输出。空偏好合法，仅按新鲜度排序。

这里的用户检查不替代仓储权限控制。未来加载器必须从服务端的同一用户、同一事务快照读取条目和启用/删除标记，不能让客户端提交伪造的候选、first_seen 或 enabled。纯函数无法识别查询遗漏；未来加载器需探测第 501 条和字节超限，并明确失败，不把前 500 条假称为完整候选集。

## 时间与评分

日窗口固定为 UTC 的 `[day_start, day_start + 86400000)`，日起点必须整除一天。as_of 位于该日内或恰好日末，使用 UTC 毫秒整数，拒绝加法溢出及超过 PostgreSQL BIGINT 的时间。只有首次保存时间在该日内、当前启用且未删除的条目参与排名。

未来首次创建只针对当天当前快照；不能用已经更新过的当前条目伪造过去某时刻的日报。历史日报应读取当时保存的计划；当前实现不提供版本化条目历史或任意日期回放。

| 因子 | 分值 |
| --- | --- |
| 某关键词在标题中命中 | 12 |
| 标题未命中，但摘要命中该关键词 | 6 |
| 距首次保存不超过 6 小时 | 40 |
| 超过 6 小时且不超过 12 小时 | 30 |
| 超过 12 小时 | 20 |

关键词采用 Unicode 小写后的直接子串匹配，不分词、不做语义扩展或 Unicode 兼容字符归一化。每个词只加分一次，标题优先，不按重复出现次数加分。最高 100 分。新鲜度只用 as_of 与 first_seen 的差值，重新抓取、正文更新或伪造发布时间都不会重置它。条目可能通过重复关键词等方式影响这个简单分数，所以产品只能将它解释为规则相关度。

排序依次为总分降序、首次保存时间降序、规范订阅 UUID 升序、条目键升序；同样的窗口、偏好和条目内容总能重建同一输出。

## 去重与数量约束

首先按当前用户内的 `(subscription_id, entry_key)` 合并完全相同快照；同键内容、时间或启用状态冲突时整体失败，不能根据输入顺序挑一个版本。

排名之后仅对规范链接、标题、摘要全部相同的条目进行保守去重；双方没有链接时也按标题与摘要完全一致去重。不删除追踪参数，不做语义、大小写、相似新闻或全文去重；同一链接正文不同仍保留为不同候选。发布时间不参与内容组身份。

每份日报最多 20 条，每个订阅最多 3 条，按稳定排序贪心选择。若某个内容的首选订阅已经达到上限，仍允许后面的其他订阅提供相同内容，防止去重提前吞掉可用候选；输出不是全局最优或等额分配算法。

计数定义：candidate_count 为复合键去重后的快照数；eligible_count 为日期和启用状态筛选后的数；duplicate_count 为这些候选中重复内容的额外行数；omitted_count 为因上限未选入的不同内容组数。因此 `eligible_count = items.len + duplicate_count + omitted_count`。空日报是合法结果。

## 版本与摘要

版本固定为 `rss-rule-brief-v1`。评分、匹配、时间或去重策略变化必须升级版本。

input_digest 对规范化、复合键排序后的完整输入快照计算 SHA-256，包含后来被排除的条目；完全相同的重复输入行不改变这个摘要。计划 digest 再绑定版本、用户、请求 ID、日期窗口、截点、规范偏好、input_digest、计数、选中条目和分数依据。摘要使用 JSON 明确字段边界，避免直接拼接字符串歧义。

摘要不是秘密、签名或执行授权。未来服务端必须自己加载数据并保存计划，不能信任客户端提交的计划或摘要。历史输入发生变化时可以得到不同计划；同 request_id 重试应返回仓储中原计划，不能在无提示的情况下替换。

## 验证与下一步

离线测试覆盖规则分值和边界、来源发布时间不参与评分、输入/偏好乱序稳定、复合键冲突、跨订阅去重与订阅上限、总量上限和省略计数、UTC 午夜、时间异常、跨用户及超限拒绝、不可信正文只作文本、计划内容变化导致摘要变化。

已落地[日报偏好与不可变计划仓储](sprint-4-rss-brief-store.md)：同一事务读取有界快照，保存规则版本、偏好、输入摘要与输出；实现当前用户范围内的请求幂等和列表/读取，下一步接 HTTP 与页面。必须同时处理订阅删除后的派生正文清理或日报失效，以及用户删除的级联清理；保存日报不能成为绕过原条目删除或账户隔离的途径。自动采集、自动派发、模型评分/总结及邮件推送仍不在本步范围内。
