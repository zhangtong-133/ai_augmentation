# Sprint 3：模型 Agent 供应商适配与一次性执行器

## 当前交付

`agent_core::model_executor::ModelAgentExecutor` 在两次独立精确授权后，分别执行规划，以及顺序查询向量化、知识检索和受限回答。复用已有 PostgreSQL 领取、金额/次数预留、证据核验及原子结算。新增供应商端口 `ModelAgentProvider`、无模型调用的 `ModelRetriever`、官方固定模型实现 `OpenAiAgentModels` 和 `KnowledgeModelRetriever`。

本步提供内部可组装能力，不注册 HTTP 路由、不读取环境变量、不启动后台任务、不启用真实付费调用。下一步为显式部署配置、两阶段 HTTP 授权与页面接入；不得复用普通知识搜索入口绕过第二阶段预算。

## 授权与派发

应用先使用仓储登记不可变配置、创建报价，用户精确批准后分别调用 `approve_planning` 和 `approve_execution`。只有首次批准返回 `started=true` 才继续领取；重放批准仅返回原请求，不扫描待执行队列、不恢复中断调用、不自动批准第二阶段。每个领取凭据都必须在 COMMIT 成功后才交给执行器。

规划执行器从冻结快照重建固定提示和查询协议，复算并匹配报价指纹，验证消息版本、请求状态及持久化配置后才发送。第二阶段每次领取携带完整冻结配置，执行器逐字段匹配本实例配置，再检查状态、消息版本及配置停用。检索严格按授权查询顺序执行；只有持久化成功才可领取下一步。已派发状态下的完成事务失败直接停止，不重试模型。读取/取消仍按既有超时规则收敛。

规划及回答使用 35 秒执行器超时；供应商 HTTP 总超时 30 秒、连接超时 5 秒。检索只读操作另限 10 秒，保持单步骤低于仓储 60 秒派发期限。向量化完成后再次读取阶段状态，取消或过期则不再检索。空证据由仓储直接终止并退还未调用的回答预算。

发送前检查不能撤回已经发送的请求；取消竞态可能保留一个已领取尝试的全部费用。网络失败、HTTP 错误、超时、存储异常均不会被解释为“未计费，可以重发”。没有完整可信 usage 时保留全部预留；已确认成功且 usage 完整才退差额。

## 固定供应商契约

适配器仅连接官方 HTTPS 固定端点，禁用环境代理、重定向和 reqwest 自动重试，不开放任意 base URL。可注入本地端点的构造函数仅为模块私有测试路径。密钥只保留于敏感认证头，错误和日志不包含凭据、对话、证据或原始供应商响应。

| 调用 | 固定模型 | 输入预留上界 | 输出上界 | 计数版本 |
| --- | --- | --- | --- | --- |
| 规划 | `gpt-4o-mini-2024-07-18` | 128000 | 2048 | `o200k-0.12.1-agent-context-v1` |
| 回答 | `gpt-4o-mini-2024-07-18` | 128000 | 1024 | `o200k-0.12.1-agent-context-v1` |
| 查询向量化 | `text-embedding-3-small`，1536 维 | 8192 | 0 | `cl100k-0.12.1-8192-d1536-v1` |

价格与价格版本由部署端显式提供，只接受 USD，不内置当前市场报价。每次请求完整匹配冻结预算（包括模型、配置/计数/价格版本、价格、有效期与 token 上界）。聊天采用现有回复适配的完整上下文窗口保守预留；本地 BPE 计数不冒充最终账单。向量化使用单条输入，只计输入费用。依据：官方 [GPT-4o mini 模型说明](https://developers.openai.com/api/docs/models/gpt-4o-mini)、[Embedding 指南](https://developers.openai.com/api/docs/guides/embeddings)、[结构化输出指南](https://developers.openai.com/api/docs/guides/structured-outputs)（2026-10-01 核验）。

聊天请求仅 system/user 文本、非流式、单条 choice、`store=false`、`service_tier=default`，按阶段提供严格 JSON Schema，不附带 tools/functions 或其他付费能力。正文总量限 49200 UTF-8 字节；本地正文与 Schema token 数限 110000，为消息封装和输出留出余量，仍按整个上下文窗口预留输入。向量化仅允许 1000 字符以内的非空查询，特殊 token 字面量按普通文本计数，不做命令解释。

响应读取最多 128 KiB。聊天复用已有模型/服务等级/choice/finish_reason/工具调用/usage 核验；结果形状及引用仍由仓储严格解码。Embedding 核验唯一第 0 项、固定模型/维度、有限且非全零向量；只有正整数 `prompt_tokens == total_tokens` 且无额外 usage 字段才结算差额。不完整 usage 保留全部预留；即使部分 usage 缺失，已观察到的越界仍视为契约异常。

模型、服务等级或用量上界契约异常会立即锁闭适配器和执行器实例，并尝试持久化停用两阶段配置；即使停用写入失败，本实例也不继续发送，下次调用只重试停用写入。其他已在途请求不能撤回。部署者需调查契约异常并登记新配置，不能重启后继续使用被持久化停用的旧配置。

## 检索接入

`KnowledgeModelRetriever` 接收执行器已经生成的向量，复用原知识检索的相似度门槛、向量模型/维度、所有者文档查询、权威片段比较和去重。该接口没有 EmbeddingProvider，因此不会隐式再产生一次付费向量化。普通知识检索仍先自行向量化，再调用相同的召回核验逻辑。

部署时检索器模型与维度必须匹配已有索引；不自动重建或迁移向量集合。检索器只返回已核验的文档 ID、分块序号和正文，仓储保存时再次复核所有者和正文。向量存储/文档存储故障向上传播，不能伪装为空证据。工具次数和审计由第二阶段领取/结算统一处理，不再调用普通工具的 `start_tool_call`。

## 配置与兼容

没有数据库迁移或新环境变量，不改变默认付费开关。第二阶段内部领取凭据增加完整配置，不向浏览器序列化；既有持久化格式和报价保持兼容。知识库 crate 引入 agent-core 以实现检索端口，不把供应商实现放入领域层。应用组装时分别注入同一 PostgreSQL 仓储、固定模型适配器及只读检索器。

当前没有自动扫描恢复；首次批准后进程在领取前退出，请求保持原状态，后续重复批准不启动发送。用户可取消并重新发起新规划。这是一次性发送与未知提交回执下的保守行为。
