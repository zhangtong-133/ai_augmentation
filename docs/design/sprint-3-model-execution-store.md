## 来源、报价与配置

每个成功的第一阶段规划请求只允许一个第二阶段报价，使用同一用户/对话/规划请求 ID。创建只能从数据库读取 `succeeded` 规划的冻结快照和严格解码后的有序查询，不能接受客户端自报建议。复核消息版本，并沿用纯模块指纹，将原规划指纹、查询顺序和 limit、向量化/回答预算、精确金额、分类次数和期限绑定到第二次确认。第一阶段已结算支出不会重复预留。

`model_execution_configurations` 冻结一组向量化/回答预算与阶段/日限额；组版本必须等于回答预算配置版本，保证版本包含在原有报价指纹中。登记、预览、批准、领取及发送前检查均核验不可变配置和数据库时钟下的价格有效期。相同版本仅允许完全一致重放；停用不可逆，usage 越界会停用整组配置，包括终态后的迟到越界报告。两种调用必须同币种，向量化仅计输入，回答输出上限为 1024。工具日上限不能超过现有全局 100 次限制。

报价最长五分钟，不晚于两种价格的有效期。同键重放返回旧阶段，不能换配置或重新报价；消息和配置变化不修改已保存的报价。预览不扣款，阶段数量受父规划的对话/用户预览额度约束。阶段记录不复制完整消息快照，领取时从父规划恢复并校验。

## 原子预算和工具审计

批准必须精确匹配原指纹、币种、金额、`chat=1 / embedding=N / tool=N` 及主动费用确认。相同批准重放返回原状态且 `started=false`；这不是发送资格。操作沿用用户→对话锁，再锁日账本，确保以下写入一起提交：

- 同币种金额复用 `reply_money_daily`，包含既有回复、规划、检索和回答。
- 聊天及向量化次数复用 `model_agent_daily`，一次性预留 N+1 次。
- 工具次数复用 `tool_daily_budgets.used`，批准时预留 N 次，领取时不再增加；普通工具和固定 Agent 计划也会看到这些占用。
- 每个付费步骤生成独立调用 UUID，对应一笔 `reply_money_reservations`，类型为 `model_execution`。每次向量化单独向上取整，再加回答预留。

配置切换、进入新阶段或删除对话均不能重置已派发占用。任一金额/次数不足或 COMMIT 失败，整批批准回滚；不会返回可用授权或领取凭据。

`tool_daily_budgets.used` 现在也包含第二阶段尚未派发的工具预留，因此审计次数可能暂时大于实际 `tool_calls` 条数。每次检索领取时插入已有工具审计表，使用共用参数指纹计算和已预留的原日期，禁止再通过普通 `start_tool_call` 扣一次次数。该 ID 已存在时，普通工具入口只返回旧记录，不再次执行。完成时同步更新工具审计；失败/未知仍保留尝试次数。

## 逐步领取和收敛

阶段状态为 `draft → queued → running → succeeded/failed/unknown`，另有 `insufficient_evidence/cancelled/expired/stale`；每步状态为 `reserved → dispatching → succeeded/failed/unknown` 或 `cancelled`。先按查询顺序完成 N 个检索步骤，再允许领取回答步骤。任何前置步骤未成功都会阻止后续领取。

每步领取重新核验父规划、消息版本、持久化批准、配置、完整指纹、逐次金额凭据和日账本；生成随机 `claim_id` 与 60 秒期限，COMMIT 成功后才返回冻结快照、单步预算和可选查询。领取不增加次数；重启、多实例、重复领取和越序领取均不能产生第二份发送权。发送前检查配置的内部端口不能替代领取，也不能撤回已经发出的请求。

完成必须匹配原 claim。及时成功且适配器核验过的 usage 才退差额；没有 usage 的成功调用保留全部预留。失败、未知、过期或越界全额保留该已派发调用，并立即取消和退回所有未派发步骤的金额、模型次数及工具次数。已成功步骤的结算不受之后的失败影响。重复完成/迟到结果不能覆盖已结算金额；领取后的消息版本变化不接受成功结果。

取消与领取共用用户/对话锁：未派发步骤退回原日预算，已派发步骤按 unknown 保留全部预留，不能再次领取。读取或操作当前阶段时处理报价到期与步骤超时；尚无后台扫描，重启不会自动重发。阶段终态重放不重新激活。

## 清理与只读运维

删除对话先收敛第二阶段，再清理第一阶段，保证未派发预算先退款；删除第二阶段记录会清除其中的查询与授权详情，父规划快照和查询随后一起清除。金额凭据、模型次数及脱敏步骤审计独立于对话墓碑保留，用户删除时级联清理。

`model_execution_call_audit` 仅记录所有者、对话、付费调用 UUID、父请求、序号及状态，不含查询、证据或答案。共享 `reply-operations ledger` 明细显示新凭据类型和步骤状态，汇总覆盖每笔费用，不重复计阶段总额。只读运维账号需额外获授此表 `user_id/conversation_id/request_id/status` 四列 SELECT，无需读取阶段 JSON。

取消第二阶段不撤销已经成功的第一阶段；父规划的原建议依旧按第一阶段保留策略保存，直到删除对话。第二阶段自身的取消/失败/到期记录不再保留查询副本。
