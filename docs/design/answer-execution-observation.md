# 问答执行自动跟踪与结果展示

2026-10-23：补齐[单次执行](answer-execution.md)之后的等待体验。用户不再需要反复点击查询；在提交执行成功或主动打开运行中的历史详情后，页面自动读取已保存的状态，终态到达后展示已校验结果。本阶段不新增模型请求、运行器或质量评测。

## 用户流程

创建预览、双重确认和另行执行一次保持原有顺序。只有详情已有 `running` 执行时开始跟踪；刷新历史列表不会自动打开正文或观察所有记录。重新加载页面后，用户先刷新列表、打开目标记录，再恢复该请求的跟踪。列表同时显示执行状态，区分运行中、成功、失败和未知。

跟踪使用既有 `GET /api/knowledge/answer-authorizations/{id}`。每次成功读取仍为 running 时，等待两秒再读；不并发读取，每轮最多两分钟，每个 HTTP 读取最多二十秒。服务器原有领取后至多九十秒的截止/回收逻辑保持不变；浏览器达到观察期限只暂停跟踪，不自行把执行改成失败或未知。

用户可暂停或继续自动跟踪。暂停不取消执行；暂停期间的“查询执行状态”只核对一次，仍保持暂停。关闭详情、刷新列表、切换请求或重新检索会停止原跟踪。页面离开前台或断网同样暂停，返回前台、联网后由用户继续，避免隐式重连。运行中的取消按钮一直可用，不因状态读取而锁住。

最终状态自动停止读取。成功展示保存的问题、答案、引用及原文高亮；证据不足独立显示。失败、未知、取消和来源失效不展示正文。自动跟踪只展示持久化状态和已校验的完整结果，未增加问答临时正文流。

## 请求和生命周期保护

每次响应除通过既有严格详情/引用校验外，还须匹配本轮的请求 ID、授权 digest、完整模型请求 SHA、开始时间和截止时间。列表元数据仍不携带问题、预览或答案。成功详情必须同时有问题和有效结果；已清理终态不得带问题或答案。

跟踪和显式操作使用独立 AbortController。任何显式操作先终止旧跟踪；取消、关闭、卸载、退出和账户切换会使旧控制器失去回写资格。即便底层取消未阻止响应到达，晚到正文也不能恢复旧详情或覆盖取消结果。跟踪不触发创建、批准、执行或取消 POST，不保存浏览器持久化缓存。

HTTP 错误、网络异常、格式或请求绑定异常均停止跟踪并清除详情，不自动重试。可恢复的错误保留原请求 ID，供用户显式核对；401 清除历史元数据和恢复 ID，404 移除无效恢复入口。后续 GET 复用服务器的会话、所有者、来源和 no-store 校验，不能绕过权限复核。

## 验证范围

纯客户端测试使用模拟时钟和确定性响应，验证状态推进、全部终态、两分钟上限、停止与晚到响应、HTTP/网络失败、请求指纹/时间绑定及不完整成功拒绝。浏览器在桌面 Next.js 和移动 Nginx 入口验证自动结果展示、暂停/单次核对/继续、断网和后台暂停、刷新后的显式恢复、取消/关闭/退出竞态，以及 401/404/503、摘要及引用错误后的清理和手动恢复。

本阶段无数据库迁移和部署配置变更；实际模型质量、推理延迟及真实材料验收继续独立记录。最终检查结果见[路线图](../ROADMAP.md)。
