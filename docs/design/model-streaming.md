# 流式文本协议与取消边界

本批建立供应商无关的内存状态机，并接入现有订阅 SSE 解析与完整结果路径。没有新增 HTTP 端点、数据库迁移、网页增量展示或后台发送；现有精确授权、一次领取/发送和领域结果校验继续生效。

## 内部事件契约

`personal-ai-llm::stream::TextAssembly` 管理一次调用，事件为 `TextEvent::Delta(&str)` 和 `Completed`。从 0 开始的连续 `u64` 序号与事件一起提交。缺号、重复或乱序立即拒绝并清空暂存正文，之后不得继续原序列。这个协议目前是 Rust 内部接口，不是已经公开的 SSE/JSON 协议。

最多 128 KiB UTF-8 文本、16384 个事件（包含空增量及完成事件）。字节上限不等于 token/订阅用量上限。状态机不缓存事件历史，也不执行工具或解析未完成 JSON。

Receiving 下可以读取 `partial_text`，仅供临时展示，不能写成完成建议或改变自评。收到 Completed 后隐藏临时视图，完整文本至多提取一次；空完成允许通过文本层，是否有意义由领域校验决定。完成后再收到事件为冲突，拒绝并清除尚未交付的结果。不能通过重复 Completed 取得第二份结果。

取消和中断只终止仍在接收的序列，清除暂存文本；后续事件无法恢复原序列。已交付文本的所有者负责在取消、账户切换、来源失效时丢弃其副本；状态机无法撤回已经交给调用者的字符串，也不承诺内存的密码学擦除。每个实例须由单一调用持有，账户和请求绑定由上层负责，不允许跨账户复用实例。

## 订阅传输接入

已通过 OpenAI Docs 核对[订阅模型与推理官方说明](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)：示例遍历流并检查 `response.completed`，将失败、不完整和中断与完成区分。下面的 EOF、额外事件拒绝和资源限制是本项目的明确接收策略，不是关于真实账户可用性的保证。

现有 SSE 字节解析保留 UTF-8 拆包、LF/CRLF/CR、多行 data、单事件 1 MiB 和总流量 4 MiB 限制。适配器按**本地收到的文本/完成事件**分配序号；不把内部连续序号当作供应商序号校验，也不宣称能识别供应商重复但没有标识的文本增量。与供应商身份、事件 ID 和未来网页游标的绑定是后续工作。

SSE 错误、格式错误、超限或冲突完成后，解析器永久失败并清除缓冲，不能通过后续合法事件恢复。完成事件后的 CR/LF 帧尾允许保留，其他数据拒绝。

一次 HTTP 请求收到完成事件后，暂存完成候选并继续读取到正常响应 EOF；只有期间没有错误、截断或额外事件才返回完整文本。此举避免网络拆包决定是否忽略完成后的错误。缺少完成事件、错误的 Content-Length 截断、传输错误和等待 EOF 超时均失败；不返回部分文本，不重发。响应必须在现有 HTTP 总超时（90 秒）和上层执行器更短期限内正常结束。若供应商在完成事件后一直保持连接，本版本会按超时失败，不将它当作已保存建议。

完成候选仍须经过现有核验/评分协议的严格校验和带来源复核的事务保存，才是可查询的业务成功。供应商完成不代表持久化成功。丢弃执行 future 会中断本地读取；已发送的供应商请求可能仍消耗额度，原发送标记不能清除或重用，业务超时继续按现有 unknown 路径恢复。

## 验收

纯状态机测试覆盖 Unicode 增量、未完成不可提取、结果只取一次、缺号/重复/乱序、终态冲突、取消/中断不可恢复、字节和事件上限。SSE 测试覆盖逐字节 UTF-8 与所有换行格式、错误后禁止恢复、同批数据中的额外终态/错误。真实本地 HTTP 夹具覆盖正常 EOF、跨传输块的晚到错误、声明长度后截断、完成后不关闭导致超时，以及客户端主动取消；不连接真实供应商。
