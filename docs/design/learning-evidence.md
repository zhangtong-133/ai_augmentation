# 训练证据与能力反馈

## 本轮交付边界

训练结果是用户填写的记录，不是能力证明。先提供只读证据检查：逐项关联原计划、任务、技能版本及结果请求，区分未记录、已取消、缺少文字记录和待人工核验。耗时、完成次数、备注长度均不换算成分数。检查不调用模型、不写数据库、不改变自评。

检查随计划详情返回，由当前仍可读取的计划和结果重新生成；不复制备注。删除计划或来源技能后，正文、结果与检查条目一并消失。旧计划仍然表示生成时的技能版本，不能当作当前技能的评估建议。用户可展开每项检查并直接回看同一任务的原始记录。

## 后续评估协议（尚未实现）

证据必须绑定 owner、计划 ID、任务 ID、结果请求 ID、技能 ID 与技能版本；至少包括具体练习产物、验证过程和可复查结果。自由备注只能作为待核验证据，不能因为非空就宣称证据充分。

量表按四个维度审阅：概念解释是否准确、能否独立完成练习、能否用可复现检查验证结果、能否说明局限或反例。每项状态为缺少证据、待核验或有证据支持；缺少材料时不给出总分或提升结论。量表版本、引用和逐项理由必须保存，外部链接不自动抓取。

持久化建议采用待确认、已确认、已失效状态。确认必须显式提交用户选择的自评分数、建议 ID、预期学习快照版本和技能版本；在同一事务中重新核对证据有效性。模型建议不等于客观能力分数，也不直接替换自评。重复请求幂等、不同内容冲突；来源删除清除衍生正文并使建议失效，不能通过重试恢复。

后续门槛：跨用户访问拒绝；修改技能或自评后旧确认冲突；删除证据后不能确认；并发确认只生效一次；没有证据和仅记录完成不产生分数；页面退出、失效和晚到响应清除私有材料。

## 只读检查接口

计划生成、详情查询和结果保存响应新增 `evidence_reviews` 数组，每项含 `task_id`、`skill_id`、精确字符串 `skill_revision`、可空 `result_request_id` 和 `state`。状态为 `not_recorded`、`cancelled`、`missing_note`、`unverified`，没有“已验证”或分数字段。非 ready 计划返回空数组。复用原计划查询的用户隔离、会话与 no-store 边界；不新增迁移、配置或数据库正文副本。

后端验证：Rust 格式、Clippy、单元测试通过；隔离 PostgreSQL 的学习 HTTP 用例验证了结果引用、只读查询一致性、跨用户拒绝和来源删除后清除检查条目。

## 页面检查与回看

任务表单提示记录练习产物、独立完成范围、验证步骤和未解决问题。计划中的每项任务可展开“查看证据检查”，展示材料状态和四个核验维度；已有结果可跳回原始训练记录并移动键盘焦点。检查与原任务、技能版本及结果请求不匹配时不显示；旧接口没有检查字段时保留原有计划功能。

检查组件只使用计划详情中的数据，不额外请求或缓存正文。继续复用学习面板的加载清除、操作前清除、会话到期和按账户卸载保护；删除来源后不显示核验提示。用户仍需单独填写自评，不提供推测分数或自动加分按钮。

页面验证：前端 lint、typecheck、生产构建通过；`BROWSER_SPEC=learning.spec.mjs RUSTUP_TOOLCHAIN=1.99.0 make browser-test` 的 10 个桌面/移动端用例全部通过，覆盖四种材料状态、回看焦点、刷新持久性、删除清理、失效与跨账户晚到响应；同时完整 PostgreSQL/HTTP smoke 通过。隔离栈已清理。本轮未运行其他页面的完整浏览器回归，也未运行可选公网、对象存储/向量索引或真实模型验收。

## 结构化证据保存与删除

新增迁移 `0036_learning_evidence.sql`，每项训练最多一份不可变证据。四个必填字段为 `explanation`、`work`、`verification`、`limitations`，分别记录概念解释、练习产物及独立完成范围、验证步骤与结果、局限与待验证问题。各字段去除首尾空白后为 1–2000 个字符、最多 8000 字节，拒绝除换行/制表符以外的控制字符。链接不抓取、内容不发给模型。

证据通过 `(user_id, task_id)` 外键绑定原始训练结果，再沿任务关联计划、技能和技能版本。只有已完成结果可以补充证据；首次保存还须技能启用且版本与任务一致。已有相同请求及正文重试返回当前计划，不写第二份；不同内容或请求冲突。证据不改变学习快照版本、自评、完成数或分钟数。

`POST /api/learning/plans/{plan}/tasks/{task}/evidence` 接收 `{request_id, body}`；`DELETE` 同一路径接收原证据的 `{request_id}`。两者要求会话及 CSRF，返回当前计划详情，保持 no-store。未知字段拒绝，UUID 和时间/版本沿用原有精确约定。结果条目新增可空 `evidence`，含请求 ID、保存时间、删除状态及可空正文。

删除证据清空正文并保留请求墓碑；重复删除幂等，旧请求或新请求均不能在同一任务恢复正文。原始训练备注保留，故删除结构化证据后仍可能显示备注待核验。删除来源技能或计划时，原结果清除会级联删除证据及其墓碑，旧计划失效后不能重新保存。保存/删除与技能变更复用 owner 事务锁，避免并发恢复。

本阶段只保存用户提供的材料；四项填满仍为待核验。评估建议持久化、逐项核验结论和带版本的确认评分仍未实现。

结构化证据后端验收：Rust 格式、Clippy 和工作区测试通过；真实 PostgreSQL 的学习 HTTP 用例覆盖未完成/取消拒绝、旧技能版本拒绝、严格字段与文本限制、并发同请求保存、不同内容冲突、会话/CSRF/用户隔离、删除与保存重试竞争、删除正文置空、墓碑拒绝恢复及来源删除级联清理。
