# Sprint 2：持久化索引任务与自动重试

## 范围与部署

补齐显式文档索引的任务持久化、完整文档进度、重启恢复和有界失败重试。导入文档仍不自动调用模型；用户必须显式提交任务。保留旧的同步 `/index?offset=…` 接口兼容已有调用方，但旧接口不更新异步任务的进度。

启用现有 `KNOWLEDGE_INDEX_ENABLED=true` 后，每个 API 进程启动一个后台执行循环，共用原有两个批次的本机并发额度。无需新增环境变量。当前不启用独立 `apps/worker`，不依赖 Redis；队列端口与 PostgreSQL 适配器分离，后续可迁移执行器部署。

新增迁移 `0008_index_jobs.sql`，不修改历史迁移。进度以文档和服务端索引目标为键；目标由模型 API 地址、模型、维度、Qdrant 地址及集合生成 SHA-256 标识，不包含密钥。更换目标不会沿用旧完成状态，也不会自动重新索引；切回旧目标可继续其任务。旧目标的记录保留，只有匹配当前配置的任务会被领取。

故障验收确认 OrbStack 容器重启可能改变 IP，而旧 Nginx 静态 upstream 一直缓存原地址，导致网关持续 502。网关改为使用 Docker 内置 DNS `127.0.0.11`，每 5 秒重新解析 API/Web 服务地址；该配置面向 Compose 容器网络，不适用于宿主机直接运行的 Nginx。验收在重启后同时等待 Web 和 Nginx 入口就绪。

## HTTP 契约

- `POST /api/documents/{uuid}/index-job`：无需请求体；必须登录并携带 `X-Requested-With: personal-ai`，返回 202 和当前任务。
- `GET /api/documents/{uuid}/index-job`：查询当前目标的任务，返回 200；必须登录。
- 所有响应禁止缓存；Next.js 代理支持这两个接口，使用普通 10 秒请求超时，不等待模型运行。
- 401 未登录；403 CSRF；400 UUID 无效；404 文档不存在、不属于当前用户或当前目标尚无任务；503 未启用索引或存储不可用。管理令牌不能代替用户会话。

响应示例：

```json
{"document_id":"…","status":"retrying","indexed_chunks":16,"total_chunks":34,"attempts":1,"error_code":"embedding_unavailable"}
```

`status` 为 `queued`、`running`、`retrying`、`completed` 或 `failed`。`indexed_chunks` 是从 0 连续确认成功的块数；只有所有批次成功才为 completed。`attempts` 是当前批次已领取的次数，成功后清零。错误仅返回固定脱敏码，不返回模型响应、文档文本、密钥、所有者 ID 或租约令牌。

重复 POST 不重置运行中、排队中或等待重试的任务，也不会重新执行已完成任务；failed 任务被显式重新提交后从最后确认进度继续，重置当前批次的重试预算。需要强制重建已完成索引时，暂用旧同步接口。任务状态不是向量库的实时健康检查，外部删库后不会自动检测或失效。

## 一致性、恢复与费用

入队先通过数据库 owner-scoped 查询锁定文档，同一文档并发提交串行化。后台通过 `FOR UPDATE SKIP LOCKED` 原子领取，生成新 UUID 租约，租约为 60 秒。每批仍最多 16 块、最多运行 35 秒，超时后结束本次等待。不同 API 实例可并行领取不同任务。

只有租约仍有效且令牌匹配的执行器可以确认进度。成功后立即排队下一批；崩溃后的未确认批次在租约到期后重新领取。每批最多领取 3 次（含首次、超时和崩溃），临时模型/向量库/文档存储错误在 5 秒、20 秒后重试；无效模型响应、无效进度和永久文档错误直接失败。最后一次领取后崩溃，过期扫描将其标记 failed，防止无限尝试。每个执行循环间隔 1 秒。

PostgreSQL 与模型/Qdrant 之间没有分布式事务。向量库成功但进度确认丢失时会重复本批；稳定点 ID 保证覆盖，不保证模型恰好调用一次，可能重复计费。租约阻止旧执行器更新数据库，但无法撤销已经发送的外部请求。失败不会删除文档或已写入向量。用户/文档删除时任务通过外键级联删除；残留向量清理仍属后续范围。

## 页面交互（2026-09-21）

文档列表为每项读取当前目标的任务状态；无任务时显示「建立索引」，失败时显示「重试索引」。页面提示模型费用和恢复后重复计费风险，不自动提交。排队、运行、自动重试和完成状态禁用提交，读取失败时先刷新确认状态，避免不确定提交结果导致盲目重试。

进行中的任务每 2 秒查询一次，显示连续确认的块数；完成、失败或读取错误后停止轮询。未启用索引、登录失效、网络/服务错误分别提示，不把服务故障当作未索引。每次请求最长 10 秒；翻页、退出或切换账户卸载组件时取消请求和定时器。手动刷新只读取状态，不调用模型。完成状态不保证向量库当前仍保有全部数据。

`make browser-test` 用响应夹具覆盖任务状态、显式重试、服务故障和退出清理。`make browser-test-index` 额外启动真实 PostgreSQL/Qdrant 和本地模型夹具，覆盖 Web/Nginx 双入口的实际提交、完成、刷新恢复及跨用户隔离；CI 的 index 作业使用此入口。均使用无头 Chromium，不需要前台 Chrome，也不调用付费模型。

验收：`make check`、前端 lint/typecheck/build、Compose 配置及差异检查通过。常规浏览器验收通过 10 项；最终 `make browser-test-index` 通过 3 项 PostgreSQL 测试、1 项 Qdrant 测试、双入口 HTTP 与重启持久化验收，以及 12 项浏览器测试。桌面/窄屏索引截图已检查。2 项公网浏览器用例按配置跳过；本次未运行 MinIO 专项或真实付费模型。隔离测试资源已清理。
