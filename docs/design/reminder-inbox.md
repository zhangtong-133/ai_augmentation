# 提醒已读与归档

已投递的一次性提醒支持标记已读/未读、归档与恢复。默认列表只显示未归档提醒，勾选“查看已归档提醒”进入归档列表。归档不删除提醒、不改变任务的 delivered 终态、不释放任务额度，也不触发再次投递。已读和归档相互独立，恢复保留原已读状态。

## 存储与接口

追加迁移 `0029_reminder_inbox.sql`，在 `schedule_reminders` 增加版本、已读时间和归档时间，以及按用户和归档状态分页的索引。旧记录默认为版本 0、未读、未归档；用户删除仍通过原有外键级联。

- `GET /api/reminders?archived=false&after=UUID`：用户会话下的未归档提醒，archived 默认 false；true 查询归档记录。每页 20 条，按请求 UUID 升序分页。切换列表时清空游标；归档不会使原游标失效。
- `PUT /api/reminders/{request_id}`：提交 `{"revision":"0","read":true,"archived":false}`。要求会话与 `X-Requested-With: personal-ai`，拒绝未知字段、非布尔状态和非规范版本字符串。未知或他人记录返回 404，版本冲突返回 409。
- 响应保留原投递字段，并增加 `revision` 十进制字符串，以及可空的 `read_at_unix_ms`、`archived_at_unix_ms` 字符串；成功响应为 no-store。Next.js 仅放行对应 PUT 路径。

写入先锁用户，与投递、取消和用户删除遵守同一锁顺序。实际状态改变时递增版本；当前版本或恰好前一版本的相同状态重放直接返回，不重置时间。其他旧版本拒绝，防止归档前的请求覆盖后续恢复。时间使用数据库时钟，保留仍为 true 的状态时间，清除状态时置空。

投递重放会返回包括已读/归档状态在内的当前记录，不重新插入或清空标记。仓储原有全量提醒查询和运维审计继续包含归档记录，因此归档不会被误报为投递丢失；审计权限不需要扩展到新字段。

## 页面与失败恢复

提醒收件箱独立读取和分页。正文仍由 React 按文本渲染。修改完成后回到当前分类第一页；遇到冲突、网络中断或未知响应结果时冻结修改，用户刷新核对后再操作，不自动重试旧写入。任务预览、批准和取消仍沿用原来的原请求重试协议。

请求在组件卸载时终止等待；迟到读取和修改响应不能填入另一账户。收件箱或任务接口返回 401 时清空任务、预览和提醒内容并禁用修改。浏览器终止等待不会撤回已提交事务。

## 验证范围

PostgreSQL 测试覆盖用户隔离、竞争更新只成功一个、相同请求重放、归档筛选、恢复保留已读时间、旧请求冲突、重新连接后的持久化，以及归档后的投递重放不增加记录。Tower HTTP 验证真实投递后的状态修改、会话/CSRF、严格输入、字符串版本及时间、归档列表和冲突。

双入口浏览器测试用受控提醒响应验证已读、归档、恢复、更新响应丢失、版本冲突、文本转义、会话失效和切换账号时迟到响应隔离；实际写入持久化由 PostgreSQL 与 HTTP 测试验证。无新增环境变量或外部调用，部署须先应用迁移。
