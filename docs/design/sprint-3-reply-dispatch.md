# Sprint 3：预算领取与持久化配置停用

## 当前交付

新增内部 `ReplyDispatchStore` 和迁移 `0014_reply_configurations.sql`，为后续供应商执行器提供一次性领取凭据与跨进程配置停用。后续[显式付费入口](sprint-3-paid-replies.md)已接入应用启动、配置、预留事务与页面。

## 配置登记与有效期

部署端显式登记模型、配置版本、完整 `ReplyBudget` 和价格有效期（Unix 毫秒）。版本全局唯一，绑定币种、价格/计数版本、token 上界及额度；同版本只能完全相同重放，不能覆盖价格、延长有效期或恢复停用记录。新价格必须使用新版本。同币种日账本继续跨版本累计。

有效期由部署者审核价格后指定；数据库时间检查只保证未超过该期限，不会自动发现供应商调价。配置表不保存密钥或正文，也不随用户删除。停用重复调用安全，数据库重连及其他实例能读到同一停用结果。没有自动清理或重新启用端口。

## 领取协议

`claim_budgeted_reply` 沿用用户→对话锁序，校验当前归属、未删除、queued 状态及未结算金额凭据。重算预留金额，检查账本凭据与冻结上下文的模型/配置版本、输出上限一致；再锁定已登记配置，核验完整预算一致、未停用且仍在有效期内。成功后同事务转为 dispatching，确认提交成功后才返回 `BudgetedReplyClaim`（冻结回复、预算及金额）。重复领取、历史无金额请求、缺失/过期/停用配置、已结算预算和不一致记录全部拒绝。

核验失败回滚，queued 请求保留，调用者可沿用取消端口释放次数和金额。并发领取只有一个成功；取消和删除遵循既有锁序及退款规则。提交结果未知时不返回凭据，后续仍按 120 秒过期协议收敛，不重新派发。

`claim_reply` 仍供已有夹具和金额仓储测试使用；它返回普通 `Reply`，不能作为付费发送凭据。后续执行器必须只接受新领取结果，不能在预算领取失败时退回旧端口。

## 运行时接入边界

后续已实现[内部执行器](sprint-3-reply-executor.md)的复核、发送、结算及异常停用；后续已接入[显式付费配置与页面](sprint-3-paid-replies.md)。以下限制继续适用于最终接入。

本次只提供内部仓储能力。现有预算预留端口仍可用于离线规划和账本测试，不要求配置登记；领取是配置有效性的强制关卡。未来运行时应在接受新预留前也检查配置，避免为已停用版本积压 queued 请求。

领取与停用通过配置行锁排序。停用完成后不能再成功领取，但先前已提交的领取凭据不会自动消失。执行器必须在发送前调用 `check_reply_configuration`，复核请求取消/删除状态，并处理适配器 `ContractViolation` 的持久化停用和告警。最后一次数据库检查与网络发送之间仍存在竞态，不能声称停用或取消能撤回已发请求；这些请求需要保留预算并依靠一次性结算及过期恢复处理。

后续需接入上述复核、供应商单次发送、usage 结算、显式启用配置和页面金额/未知计费说明，然后做双入口故障验收。当前尚未开放真实供应商，不调用付费模型。

## 验证范围
