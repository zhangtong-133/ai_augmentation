# Sprint 3：模型 Agent 检索证据与受限回答

## 当前交付

第二阶段完成接口从成功字节数回执改为两种内部结果：`Retrieved(Vec<RetrievedChunk>)` 和 `Answered(Vec<u8>)`。检索证据、严格验证的答案、步骤状态及金额结算在同一 PostgreSQL 事务提交；只有 COMMIT 成功才返回结果。该接口尚未接入 HTTP、页面或真实供应商，执行器是下一步。

## 证据归属与容量

执行器只能提交文档 ID、零起始分块序号和召回文本，不能指定引用 ID、标题或来源。仓储在当前用户/对话锁内，以 `user_id + document_id` 读取 PostgreSQL 权威分块并加共享锁，逐字比较文本，从数据库补齐标题和来源。外部向量载荷不作为权限依据。越权、缺失文档、过期或篡改文本、序号越界、超出授权查询 limit、片段超过 4096 UTF-8 字节均使本步骤失败，不伪装成空结果；数据库故障返回存储错误并回滚事务。

每个查询最多 5 个命中，三个查询合计最多 15 个唯一片段；按文档 ID 和分块序号跨查询去重，并按首次出现顺序生成从 1 开始的稳定引用 ID。证据数组的紧凑 JSON 总长度不超过 32 KiB，超限失败，不截断单条证据。工具审计只保存规范化命中的 JSON 字节累计值，不保存正文。

证据是保存时的权威文本快照，存于原有 `model_execution_requests.data.request.evidence`。回答领取凭据携带该快照，重连后保持相同 ID 和文本。取消、失败、过期及消息版本失效会清除第二阶段查询、证据和答案；删除对话删除整条阶段记录。成功与证据不足结果留存至对话删除。金额凭据及脱敏运维审计仍独立保留。

## 固定输入与输出协议

`agent_core::model_answer::plan_model_answer` 复用消息快照校验与最近 16 条、16 KiB 对话后缀选择，替换为固定证据回答系统提示；证据以独立 user 消息中的 JSON 数据追加，不提升为系统角色。系统提示要求将资料中的命令视为不可信数据，不执行工具或保存记忆。输出上限为 1024 token；输入字节统计包含新增证据，最多为对话上限加证据上限及 JSON 包装。字节数不是 token 数，未来执行器发送前必须按冻结配置离线计数，超预算不得发送。

原始模型输出最多 16 KiB，仅接受严格 JSON：

```json
{"insufficient_evidence":false,"answer":"有证据支持的回答","citations":[1]}
```

拒绝缺失字段、附加字段、重复键、代码围栏、非整数/越界/重复引用；非空回答最多 4000 字符、不得包含 NUL，并必须引用至少一个本次证据 ID。合法结构和引用白名单不保证答案在语义上得到证据支持。

模型也可返回：

```json
{"insufficient_evidence":true,"answer":"","citations":[]}
```

该标志不允许与非空回答或引用混用。此时调用已发送，正常按可信 usage 结算，阶段进入 `insufficient_evidence`，步骤记为成功。任何无效输出或检索/回答结果类型与步骤不匹配，均失败并保留该已派发尝试的全部预留，同时释放未派发步骤预算；不把无效原始输出写入数据库。

所有查询成功且累计证据为空时，最后一次检索完成事务直接把阶段设为 `insufficient_evidence`，保存规范化空答案，取消尚未领取的回答步骤并全额退回它的金额和模型次数。不会生成聊天领取凭据。部分查询为空、其他查询有证据时仍可继续回答。失败、超时或依赖错误不属于此分支。

重复完成不能覆盖已保存证据或答案，取消后的迟到答案不能复活请求。消息版本变化仍拒绝接受结果。领取、费用停用和取消语义沿用[第二阶段仓储设计](sprint-3-model-execution-store.md)。

## 兼容和后续接入

无新增 SQL 迁移、环境变量或运维账号权限。新 JSON 字段使用默认值读取旧记录，仍受已有 128 KiB 行上限约束。第二阶段授权指纹加入 `knowledge-evidence-answer-v1` 协议版本，防止升级后旧报价被当作新协议继续授权或领取；升级前未结束的旧报价应取消并从新的规划请求重新开始。旧成功记录没有答案，不应仅根据状态将其展示为新协议回答。

下一步接入两阶段供应商适配器及一次性执行器：检索仍须校验向量模型、相似度和索引载荷；带证据回答必须离线计数、检查冻结配置及预算、禁用重试，并将可信 usage 与完成结果一并提交。仅首次批准可启动执行，不扫描或重发旧任务。
