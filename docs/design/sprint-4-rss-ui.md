# Sprint 4：RSS 订阅与采集确认页面

## 交付范围

登录工作台新增 RSS 区域，复用 [RSS HTTP 接口](sprint-4-rss-http.md)。支持创建、编辑、停用和删除订阅，分页查看条目与采集历史，保存预览、明确确认一次采集、取消预览、查询原请求及显式恢复超时状态。没有新增迁移、服务配置或后台定时采集。

来源保存后以服务端规范化地址显示。修改使用保存的十进制版本字符串；删除前展示二次确认，说明删除条目、保留历史以及无法撤回已发送的请求。账户退出后卸载组件，切换账户以用户 ID 重新建立状态；收到 401 清除私有列表、条目、审阅和待核对操作，并要求重新登录。

## 确认和故障恢复

页面读取部署配置，默认关闭时仍可管理订阅和保存预览，不能勾选来源同意或确认联网。开启后，审阅区域展示保存的来源、订阅版本、请求 ID、确认期限、一次 GET、1 MiB/100 条/8 秒限制；用户勾选明确同意后才能提交保存的 digest。页面不自行重算摘要，不发送计划、来源替换或执行凭据。

所有写操作保留原路径、原请求 ID 和原输入，页面串行提交防止双击重复。失败显示核对原记录入口；管理操作可显式重试原输入。采集确认没有重试按钮，响应丢失后只能先 GET 原 request_id，再重新审阅当前状态，查询不发送来源请求。确认等待上限 30 秒，高于代理 25 秒。

读取 running 状态不自动派发或恢复。用户可在超过服务端 60 秒执行期限后显式恢复为 unknown；服务器仍最终校验期限。unknown 明确告知来源可能已收到请求，页面不会自动补采。关闭核对提示只清除本地提示，不撤回来源请求；刷新页面后可从服务端采集历史继续审阅。私有内容和待提交输入不保存到浏览器持久化存储或 URL。

操作、切换审阅或刷新配置后清除勾选状态。状态冲突、过期、额度、登录失效和连接故障均显示可操作错误信息。结果计数区分新增、更新和未变化；成功 HTTP 响应仍按返回状态显示采集失败或未知。

## 内容与布局

条目标题、摘要和发布时间都作为 React 文本渲染，不插入 HTML，不加载图片、附件或外部预览。文章链接只接受无凭据的 HTTP(S)，以新窗口打开并设置 noreferrer/noopener 和 no-referrer。订阅、历史和条目分别维护游标栈，支持上一页和下一页。长来源与请求 ID 换行，移动端按钮占满宽度。

## 验证

Playwright 使用隔离数据库、真实 API 和默认关闭的 Compose 栈，在 Next.js 桌面及 Nginx 移动入口验证管理、取消、刷新持久化、跨账户隔离、删除确认、丢失预览响应后同 ID 重试、丢失确认响应后只查询、订阅/历史/条目分页、危险内容纯文本、读取失败不伪装为空列表、登录失效清除数据及跨账户迟到响应隔离。网络确认与恶意条目场景使用浏览器路由夹具，绝不启用真实来源联网。管理场景生成截图用于布局检查。

下一步完善 RSS 运维核对与状态诊断，再推进价值评分和 Daily Brief；自动轮询仍未实现。

本步验证：Rust 1.98 全仓 `make check`、前端 lint/typecheck/build、103 项 PostgreSQL 仓储回归及双入口 HTTP 冒烟通过。全量浏览器首次运行 59 项通过、8 项按配置跳过，发现 RSS 移动端满宽按钮外边距造成溢出；修复后重跑 RSS 双入口 10 项全部通过，并检查桌面和移动截图。未重跑不受该局部样式影响的其他浏览器用例；8 项跳过项依赖真实索引或公网导入配置。未运行对象存储专项、未请求真实 RSS 或付费模型，隔离测试资源已清理。
