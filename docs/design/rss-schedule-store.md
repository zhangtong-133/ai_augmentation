# 周期 RSS 采集授权仓储

本阶段把[周期授权与时段规划](rss-schedule-planning.md)接入 PostgreSQL，提供内部 `FeedScheduleStore` 接口。迁移 `0030_feed_schedules.sql` 保存不可变预览、同意时刻和状态审计。尚未接入 HTTP、页面、后台候选扫描、时段领取或网络执行；创建或同意记录不会发起采集。

## 预览与同意

预览输入为订阅 ID 和 `ScheduleInput`。服务端按当前用户读取订阅，使用数据库时钟调用领域规划器。继续遵守五分钟确认期限、每 1/6/24 小时、最长七天及固定采集限制。调用方应为开始时间留出提交延迟，避免恰好落在五分钟边界。

同一用户/schedule ID 对应同一不可变预览；相同订阅及参数重放返回原记录，不更新创建时间或延长确认期限。不同参数复用 ID 返回冲突。已作废/取消记录仍占用原 ID，重新启用必须使用新的 ID、预览及明确同意。

同意只接受原摘要，在事务内重新加载订阅并调用领域校验器；用户、来源、订阅版本、频率、期限和固定策略均须匹配。有效的 active 请求重复同意只返回原确认时间，不再次审计或执行；错误摘要、取消/过期记录均不能变回 active。同一订阅最多一个 active 授权，由用户行锁和数据库唯一索引共同约束。

## 状态与并发

状态为 draft、active、cancelled、expired。取消 draft/active 后不可恢复，重复取消不新增事件。数据库触发器在订阅修订、停用或删除时，同事务取消该订阅的 draft/active 授权；应用对名称、URL 或启用状态的有效修改都会增加订阅版本。订阅未变化的幂等更新不作废授权。

仓储所有操作按用户行锁串行，沿用订阅和手动采集的锁顺序。同意与取消竞争最终保持 cancelled；同意与订阅更新竞争也不能留下有效旧授权。新授权不领取单次采集额度，后续实际执行必须和手动采集共享预算。

确认窗口过期的 draft、授权结束的 active 会在预览、同意、详情、列表或审计事务中更新为 expired，释放 active 唯一性占用。读取接口因此会持久化到期状态。失败事务整体回滚，到期状态将在下次成功操作时再次核对；调度器仍必须在实际领取/发送前直接检查期限，不能仅依赖已保存的 status。

每用户每天（数据库时钟 UTC 日）最多新建 20 个预览，所有状态累计最多 1000 条；用户锁使并发请求也不能超额。重放原 ID 不占新增额度。历史按 UUID 升序，每页最多 20 项，使用同用户游标；其他用户无法查询、批准、取消或读取审计。

## 持久化与审计

记录保存完整预览和摘要。解码时复核数据库索引字段、时间及摘要与 JSON 一致；批准前再按可信订阅重建预览。迁移使用复合用户/订阅外键，防止跨账户关联，账户删除级联清理。订阅删除会作废授权，历史预览保留用于核对，包含当时的来源 URL，沿用既有采集历史保留方式。

状态触发器与状态写入处于同一事务，仅保存 draft/active/cancelled/expired 事件及服务器时间，不复制 URL、查询参数或正文。每条授权的每种事件最多一条，重复操作不重复写入。审计接口仍按用户隔离。

## 后续执行边界

尚未提供周期采集执行凭据，未改变现有 `claim_collection` 手动同意协议。下一阶段需实现当前到期候选扫描、订阅/期限复核、时段唯一记录、共享采集额度预留和单次领取，并复用现有受限传输与结果写回；失败或结果未知不能重新发送。之后才接入默认关闭的 scheduler、会话/CSRF HTTP 与用户启停页面。

## 验证

新增真实 PostgreSQL 测试覆盖：预览幂等与不同参数冲突、错误摘要、跨用户访问、重连后原同意时间、单订阅 active 唯一性、取消防复活和私有审计；同意/取消及同意/订阅更新竞争、删除作废；draft/active 到期与唯一性释放；每日额度竞争和跨页无重复。测试只使用随机账户和本地测试数据，不访问订阅 URL。
