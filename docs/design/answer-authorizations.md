# 私有本地问答精确预览与一次授权

## 本批阶段

1. 共享纯请求构造与授权绑定：所有者、请求 ID、原样问题、明确 loopback 目标/模型、顺序选定原文和十分钟有效期。
2. PostgreSQL 持久化预览、显式双重确认、取消/过期/来源失效、审计与内部原子单次领取。
3. 会话/CSRF HTTP 与页面：从已检索片段选择材料、查看实际发送内容、保存或取消授权、恢复原请求状态；数据库及双入口浏览器验收后独立提交推送。

本地模型上一批质量为 4/7，因此本批只实现准备与授权生命周期，不调用模型、不向本地服务探测、不进行额外向量化，也不提供私有执行入口。内部领取端口只由测试验收；后续执行器须另行满足质量门槛、显存保护、执行时会话/来源复核和单次派发。用户在页面保存授权不启动模型或排队。付费路线不使用这一纯本地授权。

## 绑定规则

`local-answer-intent-v1` 固定请求内容，同一用户/请求 ID 的网络重试只能读取原请求，不能改变问题、目标或选择，也不能续期。用户只提交规范 UUID 文档标识和非负片段序号，1–5 个且不得重复；服务器按该用户的文档读取权威正文，按选定顺序分配模型引用 ID。

`local-answer-consent-v1` 在意图摘要上绑定每条来源的正文、标题、来源字段摘要、完整本地请求指纹以及创建/过期时间。问题保持原样，身份和目标均严格验证；实际请求继续使用 `local-knowledge-answer-v2` 和同一 5632 字节预算，超限拒绝而不截断。预览对象和模型正文不接受客户端回传为权威数据。

纯本地请求构造移到 `llm::local_answer` / `llm::local::wire_payload`，适配器继续复用并保留原公开重导出。这使存储与授权领域不依赖 HTTP 客户端，也便于以后替换 vLLM；没有改变 v2 发送协议或恢复失败质量为通过。

第一阶段验收：授权摘要身份/时效/目标/正文/元数据变更、重复选择与超限等 2 类纯领域测试通过；共享协议、本地传输与全仓 Rust fmt/Clippy/tests 通过。重新编译 CLI 后，7 个 v2 manifest 与上一批真实报告逐字段相同。前端 lint/typecheck/build 通过。此阶段仅纯协议与存储接口，数据库和浏览器在后续阶段验收，无模型调用。
