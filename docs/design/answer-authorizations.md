# 私有本地问答精确预览与一次授权

2026-10-22 更新：[本地问答单次执行与结果恢复](answer-execution.md)已接入本文的 v2 精确授权。执行默认关闭；工程闭环使用确定性夹具验收，本机 Qwen 的合成质量不再作为产品开发前置。历史模型成绩与失败条件保留，具体模型能力另行评估。

## 初始交付阶段

1. 共享纯请求构造与授权绑定：所有者、请求 ID、原样问题、明确 loopback 目标/模型、顺序选定原文和十分钟有效期。
2. PostgreSQL 持久化预览、显式双重确认、取消/过期/来源失效、审计与内部原子单次领取。
3. 会话/CSRF HTTP 与页面：从已检索片段选择材料、查看实际发送内容、保存或取消授权、恢复原请求状态；数据库及双入口浏览器验收后独立提交推送。

初始批次在本地模型质量 4/7 时交付准备与授权生命周期，当时不提供私有执行入口，也未调用模型、探测本地服务或进行额外向量化。现有执行器另行强制资源准入、会话/来源复核与单次派发；保存授权仍不启动模型或排队，须用户另行点击执行一次。付费路线不使用这一纯本地授权。

## 绑定规则

`local-answer-intent-v1` 固定请求内容，同一用户/请求 ID 的网络重试只能读取原请求，不能改变问题、目标或选择，也不能续期。用户只提交规范 UUID 文档标识和非负片段序号，1–5 个且不得重复；服务器按该用户的文档读取权威正文，按选定顺序分配模型引用 ID。

`local-answer-consent-v1` 在意图摘要上绑定每条来源的正文、标题、来源字段摘要、完整本地请求指纹以及创建/过期时间。问题保持原样，身份和目标均严格验证；实际请求继续使用 `local-knowledge-answer-v2` 和同一 5632 字节预算，超限拒绝而不截断。预览对象和模型正文不接受客户端回传为权威数据。

纯本地请求构造移到 `llm::local_answer` / `llm::local::wire_payload`，适配器继续复用并保留原公开重导出。这使存储与授权领域不依赖 HTTP 客户端，也便于以后替换 vLLM；没有改变 v2 发送协议或恢复失败质量为通过。

第一阶段验收：授权摘要身份/时效/目标/正文/元数据变更、重复选择与超限等 2 类纯领域测试通过；共享协议、本地传输与全仓 Rust fmt/Clippy/tests 通过。重新编译 CLI 后，7 个 v2 manifest 与上一批真实报告逐字段相同。前端 lint/typecheck/build 通过。此阶段仅纯协议与存储接口，数据库和浏览器在后续阶段验收，无模型调用。

## 持久化生命周期

迁移 `0042_answer_authorizations.sql` 保存问题、来源标识及哈希、意图/授权摘要和十分钟期限；不复制原文正文或完整模型请求。读取详情、确认、内部领取均重新读取权威来源并校验全部绑定。来源删除、标题/来源字段/片段变化或绑定损坏会使请求失效，不再返回预览。终态清除问题正文；过期在读取、列表及下一次准备时惰性处理，当前无定时清理任务。

以所有者行锁串行化状态写入，数据库时钟复核有效期。显式双重确认和相同摘要才能授权；重复确认不重复审计。原内部 `claim_answer` 保留一次领取契约：同一事务标记 consumed、清除问题并写入审计，提交成功后才返回内存快照，提交失败不返回快照；领取不证明内容已经发送，失败不能重置或再次领取。

现有 HTTP 执行使用 `AnswerExecutionStore::claim_answer_execution`，在原授权单次消费的同一事务新建执行记录；`begin_answer_execution` 另行绑定内部 token 并记录至多一次发送许可。迁移 `0043_answer_executions.sql` 保存执行状态和有界结果，详情按当前权威来源重建材料，列表只返回元数据。运行中取消或成功后删除结果均清除问题和结果，不恢复授权；详见[执行生命周期](answer-execution.md)。

每人最多 20 条活动请求、1000 条累计记录，列表只返回最近 20 条元数据，不含问题和原文。达到累计上限目前拒绝新建，未实现归档或自动删除墓碑；避免通过取消后重建绕过配额。审计随用户删除级联删除。

第二阶段验收：5 组真实隔离 PostgreSQL 测试通过，包含重连/请求幂等/用户隔离、双重确认/并发单次领取、来源变化/删除/绑定损坏、过期/取消/审计故障回滚、活动与累计配额。全仓 Rust fmt/Clippy/tests 通过（HTTP 夹具在允许 loopback 监听的环境运行），测试数据库容器已清理。前端仍沿用第一阶段检查；页面和 HTTP 为第三阶段单独验收。

## 私有 HTTP 与页面

`/api/knowledge/answer-authorizations` 支持 POST 准备、GET 最近 20 条元数据；`/{id}` 读取权威预览，`/{id}/approve` 保存双重确认，`/{id}/cancel` 取消或删除本次结果。`/{id}/execute` 只接受原摘要，成功领取返回 202 并在后台执行一次；重复请求只恢复原状态，失败或未知结果不自动重发。所有路由要求会话，写入还要求 CSRF 头；HTTP 操作限时 15 秒，后台执行最多 55 秒，成功响应 `Cache-Control: no-store`，返回前再次验证会话。请求正文拒绝未知字段，客户端不能提交正文、标题或内容摘要替代服务器材料。

页面从检索结果选择 1–5 个片段，预览明确显示已保存的问题、目标 URL、原文、完整模型请求和指纹。分享材料与本地计算两项均默认不勾选，保存后显示「已保存授权」且不发送；部署具备执行配置时才显示可用的独立执行按钮。页面不自动检索、读取历史或创建授权；刷新后可主动读取历史并恢复详情。创建和写入失败保留原请求 ID，可查询而不自动重发；确定输入错误或原请求不存在时允许重新准备。来源失效、取消或失败时清空私有正文和勾选状态，已成功结果须重新验证来源与引用后才能恢复；组件卸载会中止等待，避免切换账户后展示旧响应。此前的检索和付费引用问答入口保持原有行为。

## 当前执行配置与资源保护

`LOCAL_ANSWER_EXECUTION_ENABLED` 默认缺省/`false`。启用为 `true` 时必须配置 `LOCAL_ANSWER_ENDPOINT`、`LOCAL_ANSWER_MODEL` 和 `LOCAL_ANSWER_GUARD_SCRIPT`（项目 `scripts/local-model.mjs` 的绝对路径）；`LOCAL_ANSWER_NODE_BINARY` 可选，默认 `node`，也可为可执行文件绝对路径。目标由服务端固定，不能由浏览器执行请求更换；它须与原授权完整请求指纹及已启动监督服务的模型别名一致。

当前接法要求 native API 与[Linux/WSL2 NVIDIA 模型监督器](local-model.md)处于同一主机环境、同一项目工作区，可读取项目 `.local-model` 状态及 `/proc` 中的监督进程。标准 Compose API 镜像没有 Node 和宿主监督环境，`compose.yaml` 不透传这些 native-only 配置；仅在 `.env` 开启开关不能在标准容器中执行。

API 以独立参数运行 `NODE SCRIPT answer-admit ENDPOINT MODEL`，不经过 shell，标准输入/输出/错误均关闭，三秒限时；不向 guard 传问题、来源正文、授权 token 或会话。该子命令只核对现有监督进程、模型配置、`/props` 睡眠状态及当前 GPU 发送预算，不启动模型、不进行推理、不消费授权。模型须事先由部署者显式运行；原监督器继续按至少 6 GiB 余量预算监控，不足时停止本项目模型且不自动重启或重发。
