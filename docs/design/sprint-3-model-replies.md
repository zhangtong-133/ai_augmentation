# Sprint 3：显式模型回复

## 当前交付

`agent-core::reply::plan_reply` 实现纯上下文规划器，有单元测试；尚未接入 API、数据库任务、模型适配器或页面。无新增配置和迁移，不产生模型费用。以下持久化、额度和取消约定是后续实现要求，不代表已有运行时保障。

## 上下文规则（已实现）

- 调用方须读取当前用户有权访问的 PostgreSQL 消息快照；规划器本身不认证，也不读取 Redis。请求固定 `expected_revision`，不匹配拒绝执行，不能因后续消息改变原请求内容。
- 仅接受现有完整用户消息快照：未删除、版本等于条数、最多 100 条、序号从 1 连续递增；所有正文均通过现有 4096 字节/非空/NUL 校验，包括被省略的旧消息。空对话拒绝回复。
- 固定服务端系统提示，加最新连续用户消息后缀，最多 16 条；所有正文连同系统提示最多 16 KiB UTF-8。整条保留，遇到容量不足即停止，不跳过中间消息、不拆分 Unicode。返回版本、首条序号、省略条数和实际字节数，供持久化与页面说明使用。
- 所有持久化消息映射为 `user`；正文中的角色标记不能变成系统指令角色。不注入长期记忆、知识库、工具结果或其他对话。固定提示不是防提示注入的安全边界；不执行工具才是本阶段的能力限制。
- 请求携带输出上限 1024 token，不指定温度。16 KiB 不是 token 数、上下文窗口保证或货币费用上限；未来适配器必须落实输出限制并验证模型支持情况。

## 持久化与幂等（待实现）

新增独立回复请求表，不把模型输出写入当前仅用户可写的消息表，也不改变现有 Redis 消息版本语义。首版不把历史模型回复重新注入上下文，页面需明确这一限制。

创建需 Cookie 会话和 CSRF，正文仅接受请求 UUID、目标消息版本；模型、系统提示和预算由服务端固定。事务中校验所有者和对话存活，冻结所选上下文、模型配置版本及预算，并预留额度。唯一键按用户/对话/请求 UUID 约束；同键同参数返回原请求状态，不同参数冲突。重复请求不重新选上下文、不再扣额度或调用模型。删除后的请求不能复活对话。

状态采用 `queued → dispatching → succeeded / failed / unknown`，另有 `cancelled`。只有一个执行者能原子取得发送权，必须先持久化 `dispatching` 再调用供应商；关闭客户端、SDK、代理层的自动重试。发送后超时、断线或进程崩溃可能已经计费，标记 `unknown`，禁止自动重发。不能声称供应商“恰好执行一次”；保守策略可能在尚未真正发送时损失一次机会。用户再次尝试必须使用新请求并看到可能重复计费提示。

## 费用与取消（待实现）

- 初始运行额度拟限制每用户每天（UTC）20 次发送机会、每对话同时 1 个未完成请求；额度在 PostgreSQL 原子预留，进入 `dispatching` 后失败或未知也占用，只有未派发取消才释放。文本/输出限制和次数额度不等于货币上限。
- 开启真实供应商前，必须补充模型专用输入计数、服务端价格配置及保守费用预留/结算；未配置或无法确认计费上界则禁止启用。具体货币额度由部署者明确设置，不在代码中假定价格。供应商返回 usage 仅供核对，不能靠响应后的统计阻止超支。
- 取消与发送权竞争必须在事务中串行化；派发前取消保证不调用，派发后仅停止等待/丢弃晚到结果，不能保证供应商停止或退款。删除对话同样阻止晚到输出重新落库；结果提交时再次校验归属、删除及取消状态。
- 回复内容只作为不可信文本展示；不自动调用工具、不提取长期记忆。敏感上下文随对话删除，必要的幂等/费用墓碑只保留最小字段，保留期限需在存储阶段落实。
