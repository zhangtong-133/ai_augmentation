# 周期 RSS：单次领取与内部执行器

本阶段在[持久化授权](rss-schedule-store.md)上增加 `FeedScheduleExecutionStore` 与 `ScheduledFeedExecutor`，把当前到期时段接入已有采集/条目账本。迁移 `0031_feed_schedule_occurrences.sql` 保存时段与请求的唯一关联及发送确认时间。尚未接入后台候选扫描、scheduler 启动配置、HTTP 或页面；应用不会自动发起周期采集。

## 原子领取

内部调用者只提供用户和 schedule ID。仓储锁定用户行，读取 active 授权、服务器保存的同意时刻和当前订阅，重新构造已同意授权；以数据库当前时间计算时段。尚未到期、过期、错过窗口、已停用、来源/版本变化或已消费时段均不返回凭据。

同一事务检查时段唯一性和现有采集额度，创建新的单次采集计划、draft/running 审计、运行中账本和时段映射，再提交凭据。内部 draft 与 running 同事务创建，不产生可供用户批准的中间记录；单次计划摘要用于既有账本完整性，周期授权及其服务器同意记录才是本次执行依据。

周期与手动采集共用每用户 UTC 每日 20 次尝试额度，以及每用户最多一个 running 请求的限制。双方使用同一用户锁和额度检查函数，跨模式并发不能绕过额度。额度不足不写入时段；成功领取后即计一次尝试，即使取消、发送失败或结果未知也不退款。

时段主键绑定用户、授权与确定性 key，另有用户/授权/时段起点唯一约束，以及用户/采集请求唯一约束。同一时段在并发调用、进程重连或终态后都不能返回第二份凭据。其他时段仍须重新核对原授权的有效期与配额。

## 发送复核与结果处理

`dispatch_scheduled_collection` 复核凭据、计划、running 状态、当前订阅/授权、数据库时间和窗口；同时受时段派发截止与领取后 60 秒执行截止约束。确认只成功一次，并在事务中保存 `dispatched_ms`。时钟回退到时段起点之前不允许派发。超时或提交结果未知时执行器不发送、不重试，后续按原采集请求核对/恢复。

发送确认是事务中的执行边界。提交后到网络发送之间不能承诺与取消严格同时；已经通过复核的请求可能仍会发出。取消不撤回已发送的请求。结果写回再次检查周期授权有效性、发送记录、订阅和执行期限：已取消、过期或未获发送确认的结果不写入条目，复用 `subscription_changed` 失败原因。其他解析、去重、用户隔离、故障保留与超时恢复复用原采集逻辑。

`ScheduledFeedExecutor` 与手动执行器共用进程内两个名额，构造时将同一个仓储实例用于周期授权和采集写回。领取/发送确认/写回各有 5 秒等待上限，传输有 8 秒上限。调用者断开后任务继续持有名额并尝试完成写回。HTTP 传输沿用现有 DNS 公网校验、HTTPS、禁用代理/重定向/重试、响应大小及内容类型限制；不抓正文链接、附件或调用模型。

领取后崩溃、发送确认结果未知或写回失败均保留时段占用；原有显式恢复只把超过执行期限的 running 标记为 unknown，不重派。后台的未知请求诊断/恢复及公平候选扫描仍需后续接入。

## 运维和兼容性

采集详情、历史、日额度和审计沿用原表，周期来源可通过时段映射关联授权。保留 draft/running/终态事件，使现有只读 `feed-operations` 的账本一致性检查继续适用。时段表只保存关联 ID、key 和时间，不复制 URL/响应正文；删除账户时通过既有外键级联清理。

没有修改手动采集 HTTP 同意协议，也没有启用任何部署开关。自动 RSS 总体功能仍未完成：下一步是默认关闭的后台候选扫描/运行接入，然后提供用户配置与精确同意页面。

## 验证

新增 PostgreSQL 测试覆盖并发单次领取、跨用户拒绝、伪造凭据拒绝、重连后的单次发送确认、正常结果与运维审计一致性、两种取消时机的结果丢弃、派发窗口过期、崩溃恢复仍不能重领，以及手动/周期共享运行中限制和每日额度。内部执行器测试使用受控传输夹具，确认成功/未知结果各只调用一次，重复执行不重发。测试没有访问实际 RSS 服务。

2026-10-03 验收：Rust 1.99 `make check`、前端 lint/typecheck/build、完整 `make smoke` 和 `git diff --check` 通过。Smoke 包含 144 项 PostgreSQL 测试（新增 5 项）、生产镜像、双入口 HTTP 和重启/缓存故障恢复；补齐周期请求审计事件后，对最终代码额外复验 34 项 RSS 集成测试，含运维一致性断言，全部通过。临时服务、网络和数据已清理。没有页面变更，未重跑 Playwright、对象存储/向量索引专项，也未访问实际 RSS 服务。
