# Sprint 3：对话与用户消息页面

## 已交付

Dashboard 新增「对话与消息」：创建/选择对话、读取历史、显式发送用户消息、刷新和删除确认。复用现有 Cookie/CSRF 接口，无迁移或新增配置。这里只保存用户消息，不生成模型回复，不调用工具、不提取长期记忆。

标题按 Unicode 字符校验 1–80 字；消息按 UTF-8 字节校验 1–4096 字节。页面显示计数，每个对话最多 100 条；数据只作为文本渲染，不执行 HTML/Markdown 或来源链接。历史按服务端顺序显示，长内容可滚动。

## 请求与草稿

- 创建/发送首次提交生成 UUID，请求进行中禁用重复操作。收到并解析成功响应才清空原请求；失败保留草稿、请求 ID 和原始正文，冻结编辑，提供「重试原请求」。不自动重试。
- 未确认写入期间禁止切换对话或删除；仍可刷新相关列表/消息来核对。放弃请求需要二次确认，不会撤销可能已成功的写入，之后再次提交可能重复。
- 请求 ID/草稿只保留在当前组件内存，不存入 localStorage。刷新整个页面、退出账户或放弃后会丢失本地请求 ID，页面明确提示先核对历史。创建请求的服务端墓碑期限沿用[对话协议](sprint-3-conversations.md)，不要跨越删除后的 24 小时无限重试。
- 普通草稿在切换对话时清空。组件按用户/对话 ID 隔离；切换或卸载取消读取并忽略晚到响应。退出成功后卸载全部私有数据。取消客户端请求不保证撤销已经提交的服务端写入。
- 读取失败明确显示错误，不冒充「暂无消息」；没有成功读取当前快照时禁用发送。写入出错区分会话失效、权限、已删除、额度/幂等冲突和服务故障。
- 删除先确认整个对话及消息，失败可重复删除或刷新核对；404 视为目标已不可访问并移出页面。缓存/备份的物理删除边界沿用[消息设计](sprint-3-messages.md)。
