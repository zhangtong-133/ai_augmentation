# 私有问答来源复核与精确摘录

## 分阶段计划

1. 调用模型前、返回生成结果前复核所有输入来源与当前会话，覆盖生成期间的撤销和修改。
2. 供应商无关引用端口增加精确摘录；应用校验原文唯一位置并计算字符范围，拒绝伪造、空白、超长或歧义引用。
3. 页面展示摘录并校验范围，补齐双入口浏览器、PostgreSQL 和生产镜像验收。每阶段独立提交推送。

本批使用合成夹具，不调用真实模型，不启动 GPU，也不启用问答开关。不依赖 RSS 评分质量通过；后续私有材料的精确分享/一次授权及本地适配另行设计。原有 AnswerProvider 继续隔离供应商，后续可接入本地/vLLM。

## 第一阶段：生成边界复核

`POST /api/knowledge/answer` 在检索结束后、发送模型前，以及模型成功生成（包括证据不足）后，按原用户重新读取全部输入文档。逐一比较文档 ID、标题、来源和本次块序号对应的原文；包括模型最终未引用的输入，因为答案仍可能依赖它。随后重新验证请求会话且用户必须一致。

来源删除、改属其他用户、原文或来源元数据变化返回 `409 answer_evidence_changed`；读取失败返回 `503 answer_evidence_unavailable`；会话失效返回 401。错误仅含固定代码，不包含生成正文、数据库细节或原文；不自动重试。成功继续返回 `Cache-Control: no-store`。复核纳入原 55 秒整体超时和并发槽，不新增数据库结构或后台任务。

这些检查是生成边界的尽力复核，不是跨数据库/模型的原子锁。无法撤回已发送给模型或已返回浏览器的数据；最后一次读取后的并发变化仍可能发生。只有明确增加精确授权与单次发送机制后，才能宣称具备那一层授权保证。

验收：3 项问答 HTTP 测试通过，其中新增暂停模型夹具覆盖删除、原文/标题/来源修改、归属变化、退出登录、证据不足期间退出和未引用输入删除；另验证发送前与生成后读取失败分别导致零次/一次模型调用且不泄漏内容。全仓 Rust fmt/Clippy/tests、前端 lint/typecheck/build 通过。真实 PostgreSQL、生产镜像及浏览器验收集中到第三阶段；无真实模型质量或游戏压力验收。

## 第二阶段：严格摘录与原文范围

`AnswerProvider` 的模型引用改为 `{ id, quote }`；供应商适配器使用严格对象 schema，拒绝旧整数引用、缺失摘录和额外元数据/位置字段。模型不提供可信标题、来源或偏移。供应商无关端口不依赖任何运行时，模型 Agent 的独立整数引用协议不受此改动影响。

领域层逐条验证引用 ID 唯一且属于本次检索结果；摘录非空白、最多 400 个 Unicode 标量，必须与原文逐字一致且只出现一次（含重叠匹配）。不修正大小写、空白、换行或 Unicode 规范形式。重复短句需提供更长的唯一摘录，否则整份答案返回 `502 invalid_answer`，不返回部分成功结果。

HTTP 每条引用在原有字段上增加 `quote`、`quote_start`、`quote_end`。范围基于 `text`，从 0 开始，使用 Unicode 标量的半开区间 `[start,end)`，不是 UTF-8 字节、JavaScript UTF-16 单元或字形数；位置由服务端计算。示例 `前🙂言：证据 é\n结尾` 中 `证据 é\n` 的范围为 `[4,10)`。精确引用只证明摘录存在，不证明回答语义正确或每句话都受支持。

验收：全仓 Rust fmt/Clippy/tests 通过；3 类新增领域用例涵盖 Unicode、唯一位置、重叠、伪造、空白、400/401 字边界和整份拒绝；3 类聊天适配测试验证 schema、拒绝旧格式/额外字段及固定错误。本地 HTTP 增加伪造摘录拒绝和响应位置断言。更新隔离模型夹具与双入口 smoke 断言，脚本语法检查通过。前端沿用第一阶段结果，页面尚未改动；真实 PostgreSQL/向量检索/镜像/浏览器链路于第三阶段统一运行，无真实模型调用。

## 第三阶段：页面与双入口验收

页面严格解析 `quote` 及 Unicode 标量范围，核对原文切片和唯一出现条件；错误偏移、UTF-16 偏移、缺失摘录、重复 ID 或歧义摘录都不展示回答。引用卡直接展示纯文本摘录，展开完整片段后高亮相同范围，保留原始上下文；HTML/URL 仍按文本处理。来源变化、来源读取失败和会话失效使用不同提示，不自动重试；每次提交清空旧结果，取消等待、退出/换账户及晚到响应保护继续保留。

检索专项用例从 dashboard 拆到 `tests/browser/retrieval.spec.mjs`，仍由默认完整浏览器测试发现，也可用 `BROWSER_SPEC=retrieval.spec.mjs make browser-test-index` 同时验收 Next 桌面、Nginx 移动入口与实际索引链路。夹具测试与真实服务测试分别标明；这里的“实际索引”仍使用确定性模型 HTTP 夹具，不是模型语义质量验收。

第三阶段验收：前端 lint/typecheck/build 通过；生产镜像和隔离索引 smoke 通过，含 170 项 PostgreSQL、6 项 Redis、Qdrant 检索、双入口实际问答/引用范围、CSRF/账户隔离、索引任务与服务重启恢复。6 项检索专项浏览器测试全部通过（桌面/移动各 3 项）；包含纯文本注入防护、取消/晚到/退出、来源错误、Unicode 高亮和 16 类无效引用组合。桌面/移动摘录及 Unicode 截图已检查。Rust 沿用第二阶段全仓验收，此阶段未改 Rust。

完整浏览器全集及 S3/真实公网专项本地未重跑，由远程 CI 单独报告；本次只选择检索问答专项。模型调用全部使用夹具，不将工程验收视为真实问答质量、游戏压力或 vLLM 验收。没有迁移、配置开关或供应商凭据变更。

## 后续任务

1. 私有问答精确分享预览：冻结问题、实际发送片段、供应商/模型/提示版本和内容摘要，复用现有所有者与撤销检查，并明确向量查询本身的分享范围。
2. 持久化一次授权与单次发送：预览后显式确认、过期/取消/来源变更保护、并发领取及未知结果不重发；付费入口仍需现有金额授权约束。
3. 独立本地问答适配与合成质量集：通过同一引用端口运行 llama.cpp，保留 vLLM 替换接口；再做真实质量和至少 6 GiB 显存预算验收。未经验收不自动启用。

RSS partial 标注复核与新文档留出集继续单列，当前公开材料门槛失败不因本批问答工程验收而改变。

最终夹具补验：旧 smoke 文档的重复句子改为确定性的编号文本，使正常链路的短摘录可唯一定位，避免依赖命中次序；拒绝重复/重叠引用的领域与浏览器用例保留。调整后的 `make smoke-index` 再次通过全部数据库、镜像和双入口流程。两轮临时栈均已清理，镜像缓存保留。前两个阶段的远程 CI 截至本次记录仍运行中，不记作通过。
