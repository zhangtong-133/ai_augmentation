# RSS 评分授权与结果页面

登录后的“RSS 价值评分”面板使用[私有评分 HTTP](rss-value-http.md)。用户显式读取已绑定连接、选择模型、预览冻结内容，分别确认分享和订阅用量后保存授权；再使用[本地命令](rss-value-local.md)执行原请求。网页没有执行模型、上传凭据或后台轮询入口。不新增数据库迁移或配置项。当前日报仍使用关键词规则排序；API 金额预留和真实订阅账户验证仍待完成。

## 交互

- 连接列表每页 10 条，仅有效连接可选择；刷新或翻页清空模型选择，提交精确连接版本。
- 预览展示完整系统指令、关键词/候选输入、模型、连接版本、请求标识、摘要和期限。分享内容与订阅用量分别勾选，默认不选；到期后禁用批准，服务端最终校验期限及连接/快照一致性。
- 授权只保存同意。页面提示在本机执行 `value-run`，用户显式查询执行结果。订阅额度或账户允许的 credits 均需明确同意，不显示零费用保证。
- 历史记录每页 20 条，可读取详情和审计；候选编号对应原始标题，评分为空时展示“无法评分”。正文、标题和评分理由仅作为 React 文本渲染。历史 API 模式只读。
- 待批准、已批准、执行中可取消。取消响应确认后正文被清除；已发出的外部请求可能继续消耗用量，迟到结果由已有服务端栅栏丢弃。

## 故障与隐私

写入期间冻结其他操作。预览响应丢失保留原 ID、连接版本和模型，可显式重试原预览或查询原 ID；不会创建新 ID。批准/取消响应丢失或冲突后仅允许核对原请求，不自动重发、不自动接受新摘要。查询成功后重置两项同意；已批准记录不再出现批准按钮。404 确认后可关闭不存在的请求。

查询失败清除旧详情；响应字段、状态、时间、候选映射与评分结构校验失败时不给出批准操作。每次请求带超时和取消信号，写操作保留 CSRF 头，读取使用 no-store。收到 401 清空本面板全部私有数据并锁定操作；退出或切换账户时按用户 ID 卸载，取消中的晚到响应不能恢复旧数据。状态和用量是否有效仍以服务端复核为准。

不持久化正文、同意、连接或待核对请求到浏览器存储。重新加载页面后通过私有历史列表找回请求。

## 验收

`tests/browser/feed-values.spec.mjs` 在 Next.js 桌面和 Nginx 移动端覆盖：精确双重同意、冲突后重新确认、批准响应丢失、原预览幂等重试、取消清理、评分/审计展示、分页、到期、非法结果、401 和账户切换晚到响应隔离。不可信文本和移动端溢出同时检查；结果页截图保存到 Playwright 测试产物。浏览器故障测试使用确定性 HTTP 夹具；`make browser-test` 同时运行真实 PostgreSQL 和双网关 HTTP smoke，不调用真实模型。

本轮通过 Rust `make check`、前端 lint/typecheck/build、生产镜像构建、162 个 PostgreSQL 集成测试和完整 HTTP smoke。浏览器全量首次执行中，新增桌面端 3 个用例因下拉框标签定位超时失败；已改用精确 combobox 角色定位，并在重新生成凭据的新隔离栈中复验全部 10 个评分用例通过（原有 120 个浏览器回归也通过）。8 个依赖可选索引/公网配置的用例按配置跳过；未运行对象存储扩展或真实订阅调用。已人工检查桌面和移动端结果截图，长文本无横向溢出。
