# Sprint 4：Skill Graph、自评与训练计划纯规划

本步将 `personal-ai-learning` 的练习任务占位代码替换为 `planning::plan_learning`：校验当前用户的技能图和显式自评快照，针对用户选择的目标生成有时间预算的任务建议。规则版本为 `self-assessed-learning-v1`。本步不接数据库、HTTP、页面、模型、通知或后台执行。

## 输入与技能图

调用方提供 `UserId`、`LearningRequest`、完整有界的 `SkillNode` 集合及 `SelfAssessment` 集合。请求包含非零 UUID 请求 ID、明确的毫秒截点 `as_of_unix_ms`、5–180 分钟预算，以及 1–10 个不同目标技能 ID。

每个技能包含 owner、非零 UUID、正整数 revision、名称、enabled/deleted 和先修技能 ID。图最多 100 个节点，每节点最多 8 个不同先修；名称原始输入最多 120 字符、480 字节，禁止控制字符，去首尾空白后不能为空。时间和版本受 PostgreSQL BIGINT 范围约束，时间允许 0，版本从 1 开始。

所有 UUID 规范化，节点和先修边不能重复。先修引用必须在本次快照中存在，不能自引用或形成环。使用稳定 Kahn 拓扑排序，不使用递归；同一层按规范 UUID 排序。整个图均校验，包括不属于本次目标、停用和删除的节点，避免隐藏坏数据或恢复启用后出现环。不存在、停用或删除的节点不能作为显式目标；目标的先修节点不可用时返回阻塞原因。

## 自评语义

能力分数来自用户主动提交的 **0–100 分自评**，不是客观考试成绩或模型判定。未评估与 0 分不同。首次缺少有效自评时建议先自评，不把未知能力当成零分自动安排练习。

每份自评绑定 owner、独立非零 UUID、技能 ID、技能 revision、分数和评估时间。最多 1000 份，禁止重复 ID、不存在的技能引用、超前技能版本、超出范围的分数或晚于截点的时间。不会将非法分数自动截断至 100。

只采用与技能当前 revision 相同的记录，以时间最新者作为当前自评；旧版本记录仍被校验并计入输入摘要，但不能作为当前能力证据。同技能、同版本、同毫秒的分数矛盾时拒绝快照；若分数一致，以最大规范 UUID 确定证据 ID，避免依赖输入顺序。新自评可以低于旧自评，不使用历史最高分或平均值覆盖用户当前判断。

v1 用 **70 分**作为自评准备阈值。这是可版本化的产品规则，不是经验证的能力标准。状态含义：

| 状态 | 含义 |
| --- | --- |
| `unavailable` | 技能已停用或删除，不能安排任务 |
| `blocked` | 存在未满足的传递先修技能 |
| `needs_assessment` | 先修条件满足，但当前版本没有自评 |
| `needs_practice` | 先修条件满足，当前自评低于 70 |
| `satisfied` | 当前自评达到 70，且全部传递先修条件满足 |

即使某中间技能自评 100，只要它的先修条件未满足，也不能解锁依赖它的目标。输出包含目标及全部先修节点的状态、证据 ID、可选自评分及完整阻塞技能 ID，采用稳定拓扑顺序；删除节点只返回“已删除技能”和阻塞身份，不返回旧名称、自评 ID 或分数。

## 训练计划

只为 `needs_assessment` 和 `needs_practice` 节点安排任务：自评固定建议 5 分钟，练习固定建议 25 分钟。每份计划最多 5 个任务，合计时间不得超过请求预算；不足以容纳一个任务时不缩短该任务，也不透支预算。先安排未知节点的自评，再按当前自评分从低到高安排练习，同分按规范 UUID 排序。

每项任务含 skill ID/revision、类型、中文标题、固定练习说明、建议分钟数和目标自评分。返回 `remaining_minutes` 及 `unscheduled_ready_count`，区分预算/任务数限制与先修阻塞。达到目标且先修完备时不额外生成工作。

例如“Rust 基础 → 异步编程 → 服务开发”：基础自评 80、异步自评 40，选择服务开发目标并给 30 分钟，只建议 25 分钟异步练习，剩余 5 分钟；服务开发仍被阻塞。生成计划、安排练习或消耗时间都不表示练习完成，不会自动上调能力或解锁下一层。若预算只有 20 分钟，则没有可容纳的练习任务，并明确报告一项可安排但未排入的任务。

## 确定性、隐私与后续仓储边界

所有输入先验证 owner；跨用户的无关节点和旧版自评同样拒绝。输入类型及输出不实现包含私有正文的 Debug，内部数据库读取可严格反序列化输出计划，不暴露客户端计划反序列化入口。名称只是文本，后续页面必须按文本渲染，不执行其中的标记或指令。

`input_digest` 使用 SHA-256，绑定规则版本、owner、规范请求、全部规范技能与自评；停用、未选中和旧版本数据均包含在内。顺序、UUID 表达形式及名称首尾空白差异不改变语义摘要。输出摘要绑定完整计划。任务 ID 由 owner、请求、输入摘要、技能和任务种类确定性生成 UUID v5。摘要和 ID 都不是签名、秘密、执行许可或已完成证明。

纯函数不能判断调用方是否遗漏数据库行，也不提供同 request ID 的持久化幂等性。下一步仓储必须：

- 在当前用户的同一事务快照内加载图、状态和自评；用数据库时钟产生截点，探测上限外一行，超限明确拒绝，不能静默截断。
- 对技能修改和自评追加做版本/CAS、所有权和额度控制；技能变更增加 revision，旧自评不会自动迁移到新含义。
- 原子保存不可变计划及派生任务，原请求重试返回原记录；配置、图或自评变更不能替换已保存快照。
- 技能删除清理名称与自评，并清除/失效包含其派生正文的历史计划和任务；保留必要墓碑避免原 ID 复活，账户删除级联清理。
- 任务完成、取消与重新自评均为显式操作。即使用户标记练习完成，也不得自动增加自评分、生成新计划、派发 Scheduler 任务或调用模型。

## 验证与路线图

单元测试覆盖未知与零分、阈值边界、直接/传递依赖、菱形依赖和最大深度、重复/缺失边和环、跨用户输入、停用/删除、旧版本/未来/矛盾自评、分数下降、规范化及排列不变性、时间和数量上限、精确预算、输入/输出摘要绑定与删除正文抑制。

纯规划阶段无数据库迁移或应用配置变更。后续[技能图、自评记录与不可变训练计划仓储](sprint-4-learning-store.md)已实现；[HTTP、页面和用户显式训练结果记录](sprint-4-learning-app.md)也已接入。
