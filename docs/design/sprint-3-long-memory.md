# Sprint 3：用户显式管理长期记忆

## 范围

登录用户可在 Dashboard 的「长期记忆」新增、查看、编辑和删除自己的事实/偏好。仅保存用户手动输入，不自动提取聊天、不发给模型、不用于当前问答，不进入向量索引或工具上下文。Redis 短期记忆和模型记忆建议另行交付。

新增迁移 `0009_long_memory.sql`，API 启动时执行。`memory_facts` 使用 UUID 主键、用户外键、标题、内容、版本及创建/更新时间；删除用户时级联删除。存储接口为独立 `LongMemoryStore`，不混用原来的对话短期记忆接口。无新增配置。

## HTTP 协议

所有接口需要 Cookie 会话，写请求还需 `X-Requested-With: personal-ai`；管理 token 不能代替会话。Next.js 与 Nginx 均支持，成功响应 `no-store`。

| 接口 | 请求 | 成功结果 |
|---|---|---|
| `GET /api/memories?offset=0` | offset 为 0–100，默认 0 | 200；按创建时间和 ID 倒序，每页最多 20 条 |
| `POST /api/memories` | `{"title":"回答偏好","content":"中文且简洁"}` | 201；完整记录，初始 version=1 |
| `PUT /api/memories/{id}` | title、content 和当前 version | 200；新记录，version 加 1 |
| `DELETE /api/memories/{id}` | `{"version":1}` | 204；无响应体 |

记录包含 id、title、content、version、created_at_unix_ms、updated_at_unix_ms，不返回所有者 ID。标题 1–80 字符、内容 1–2000 字符，不能全为空白或含 NUL；拒绝额外字段及客户端所有者。每用户最多 100 条，通过事务内锁定用户行并检查配额避免并发超限。编辑/删除必须匹配版本，冲突返回 409，防止静默覆盖；跨用户或不存在的 ID 都返回 404。

分页不是跨请求快照：其他页面新增或删除时可能发生位置变化，可刷新重新查看。创建没有幂等键；网络中断后写入可能已成功，先刷新确认，不自动重试。服务失败不能伪装成空列表。删除会从当前数据库移除记录，不提供页面撤销；已有数据库备份仍需遵循部署方保留策略。

## 页面行为与安全

展示纯文本，不执行 HTML 或来源链接。编辑冲突保留输入并提示刷新；刷新会清空编辑表单。删除先展示确认按钮。写入期间禁用重复操作；请求超时提示刷新确认结果，不自动再次写入。退出或切换账户卸载组件，清空列表/草稿并取消客户端请求；不能保证取消已经提交的服务端写入。提醒用户不要保存密码等敏感凭据。

- Rust/API：认证、CSRF、参数限制、伪造身份、存储失败不返回空列表。
- PostgreSQL：所有者隔离、并发版本竞争、旧版本删除拒绝、重连持久化、并发配额、分页与用户删除级联。
- `make browser-test`：两入口 HTTP CRUD/版本冲突/重启持久化；桌面与窄屏页面新增、编辑冲突、纯文本渲染、删除确认、刷新与账户隔离。浏览器登录按最小间隔遵守真实登录限流，不关闭保护或重试失败请求。
