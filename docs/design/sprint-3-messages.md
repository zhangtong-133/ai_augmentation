# Sprint 3：持久化用户消息与 Redis 快照

## 范围与存储

新增迁移 `0011_messages.sql`：PostgreSQL 保存用户消息、请求 ID、顺序和对话版本；删除对话时清空消息并写入缓存清理待办。与只存短期缓存不同，消息正文**持久保存到用户删除对话**，Redis 过期不删除历史。当前不调用模型、不接受 assistant/system 角色、不写入长期记忆；[管理页面](sprint-3-conversation-ui.md)已交付。

每个对话最多 100 条消息，每条 1–4096 UTF-8 字节，不得全为空白或含 NUL。满额后新请求返回 409，但相同请求重放仍成功；不静默裁剪。对话仍受每用户 100 个未删除对话及滚动 24 小时 100 次创建额度约束。后续扩容必须重新设计分页、配额及幂等保留，不能直接删旧记录来绕过上限。

## HTTP 协议

沿用 Cookie 会话与写请求 `X-Requested-With: personal-ai`，所有者取自会话，成功响应 `no-store`。Next.js/Nginx 双入口均支持。

| 接口 | 输入 / 输出 |
|---|---|
| `POST /api/conversations/{id}/messages` | `{"request_id":"UUID","content":"你好"}`；首次/重放均 200，返回 id、sequence、content、created_at_unix_ms |
| `GET /api/conversations/{id}/messages` | 200；`{"revision":1,"deleted":false,"messages":[…]}`，按 sequence 从旧到新，最多 100 条 |

全部消息均为用户提交，顺序和时间由服务器生成；拒绝 role、user_id、sequence、客户端时间等额外字段。会话失效 401、CSRF 403、无效内容/ID 400、结构不符可为 422；外人/不存在/已删除对话 404；同请求 ID 不同内容或满额 409；数据库故障 503，不用缓存绕过数据库认证或伪装空列表。

请求 ID 在对话内唯一，幂等保留至对话删除；并发重放只写一条，网络结果不确定时可用**相同 ID 与相同内容**重试。新消息在对话行锁内校验归属/删除状态、检查额度、插入并递增版本。读取数据库快照持有共享锁，版本与正文不会来自不同提交。

## Redis 与删除一致性

`MESSAGE_CACHE_ENABLED=false` 为默认；设为 `true` 后要求 `REDIS_URL`，Compose 已透传，URL 无效拒绝启动，连接故障不阻止 PostgreSQL 消息读写。Redis 是可丢弃缓存，不承诺其持久化。

- 新 `messages:v1:` 命名空间使用用户/对话摘要键；缓存完整快照，最多 3 MiB/键，固定 30 分钟 TTL。读取和同版本重试不续期；不同版本替换后重新计时。与原 `MemoryStore` 的 `memory:v1:` 追加接口独立，不受其 32 个活跃对话配额控制。
- 每次 GET 首先从 PostgreSQL 检查归属、未删除状态和当前版本。仅接受相同版本的非删除缓存；缓存缺失、损坏、过期、故障或版本不符时读取数据库并尝试重建。写消息只提交数据库，不因缓存故障返回写入失败。
- Redis Lua 仅接受更高版本，删除缓存以更高版本的空快照覆盖正文，防止晚到的旧快照覆盖删除栅栏。即使 Redis 重启丢失栅栏或栅栏过期，数据库的删除状态/版本检查仍阻止旧正文对外可见。
- 删除在 PostgreSQL 事务内与追加互斥，清空消息、递增版本、标记持久化清理待办；204 表示权威删除成功，**不表示所有缓存和备份已物理擦除**。启用缓存时 API 内任务每批最多处理 20 项，批次间隔 5 秒；缓存写入成功才确认，进程重启/Redis 恢复后继续，多实例重复执行安全。
- 未启用缓存时不运行清理任务；原缓存自然 TTL 到期。待办随对话墓碑至少保留 24 小时，之后可由原有创建事务清理。Redis 连接/命令共用每次 2 秒超时；取消不能撤销已经发出的命令。数据库备份和 Redis 持久化文件沿用运维保留策略。

删除前已开始的读取可以返回旧快照；删除提交后开始的读取与追加均被拒绝。缓存故障最多增加读取延迟，不降低归属检查。Redis 仍需私网/访问控制和实例内存预算；摘要不加密正文，日志不记录正文或凭据。
