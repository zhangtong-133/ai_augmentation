# Ollama 候选完整双轮离线比较

2026-10-15：将原先临时运行的跨 profile 比较纳入正式 CLI、Make 和 CI。它比较同一模型/运行时下的两组完整观察，分别记录整题和每项检查的变化。v17 总分改善但既有失败题的部分检查退步，不能只看净增分。

```sh
make ollama-answer-compare LEFT='左侧十六份报告路径' RIGHT='右侧十六份报告路径'
# 路径含空格时，直接调用 CLI 并分别引用每个路径：
node scripts/ollama-answer-benchmark.mjs compare --left 左侧十六份路径 --right 右侧十六份路径
```

该命令只在本机离线构建合成 CLI 并重建 manifest，不访问 Ollama、下载模型或发送推理。两侧分别支持 v14 cold、v15 reuse、v16 question 和 v17 guarded，也可比较同一 profile 的不同观察。默认模型和业务路径保持原状。

## 输入与配对

两侧各自必须满足现有完整质量门槛的结构和资源条件：八套各两份完整报告、严格 schema、同一 profile/运行时、当前 CLI 的完整 manifest、逐题四项布尔检查、计数一致，以及每题两次或三次发送许可。质量失败的完整报告可以比较，协议中断、缺轮或单题诊断不能混入。两组并不合并为新的质量门槛。

跨组仅允许 execution_profile 和 resource_policy 不同，其余运行时字段必须一致，包括 Ollama 版本、运行器、loopback URL、模型别名、digest、元数据摘要、模型大小、平台、架构及总内存。两侧每个原始 case 对象须完全一致，包含资料/协议摘要、预期状态、正反关键词、引用和顺序；实际请求分别对照各自当前 manifest，不能通过改写预期结果比较不同题目。

按固定套件顺序、每套 started_at 从早到晚配对第一、第二轮。命令参数顺序不改变配对和结果；32 个 run ID 必须各不相同，全部观察区间不得重叠。报告内的数据不能证明这些是历史上最早的运行，因此调用者仍须保存首次完整双轮，不能补跑选优。

报告须位于项目 `.local-model/quality/` 内，报告根目录不得为符号链接；拒绝重复路径/字节、末级符号链接、目录、超过 65536 字节、无效 UTF-8 和非法 JSON。gate 与 compare 共用有界读取器；实际读取使用不跟随末级链接、非阻塞文件打开和严格 UTF-8 解码，不只依赖读取前的文件大小。

## 输出

新建 `ollama-answer-quality-comparison-v1` 私有报告，目录 0700、文件 0600，不覆盖输入。报告总大小继续限制为 65536 字节，全部 71 道题的最坏变化组合已覆盖测试。标准输出提供报告路径及同一份结构化结果；失败只输出固定阶段，不回显文件正文。

每个题目保留两轮整题、引用范围有效性，以及 expected_status、required_terms、expected_citations、forbidden_terms 的转移；另给出全局和逐套整题统计。转移名称含义如下：

| 名称 | 左侧 | 右侧 |
| --- | --- | --- |
| passed | 通过 | 通过 |
| failed | 失败 | 失败 |
| improved | 失败 | 通过 |
| regressed | 通过 | 失败 |

因此 `quality.regressed=0` 仍可同时有检查项退步。四项检查共 568 次配对；引用范围有效性单列，不混入四项检查数量。保留每侧 profile、资源策略、门槛 schema/结果、原规范化 manifest 摘要、每份规范化报告摘要/run ID/轮次、通过数量、每题请求数及耗时中位数。摘要与原 gate 使用相同规范化算法，不是文件原始字节摘要。

不保存问题、资料、模型回答、摘录、证据 key 或关键词列表。检查项转移只能比较已经保存的布尔判定，无法在没有原始回答时独立重判语义。耗时来自历史观察，不能据此证明性能因果或游戏并行表现。

退出 0 表示比较确认且两侧质量门槛都通过；2 表示可比较但至少一侧质量失败；1 表示输入/构建/比较未确认。`private_execution_authorized` 始终为 false；不能将跨 profile 的局部最好结果拼接成通过。

## 验收

新增 9 项 Node 测试覆盖全部 71 道冻结题、整题改善但检查项退步、参数换序、四种 profile、运行时/模型和题目条件变化、重复/重叠观察、诊断混入、资源计数、受限读取、最坏报告大小和错误正文不外泄。已加入 `make local-answer-quality-test` 与远程 CI。

用历史首次完整报告实际运行两次新命令，分别按当前 Rust CLI 重建双方八套 manifest，均退出 2，符合原始失败状态。新报告的字段、目录/文件权限和大小均独立核对；没有重新调用模型。

| 左侧 → 右侧 | 通过次数 | 整题改善 / 退步 | 检查项改善 / 退步 | 每题耗时中位数 |
| --- | --- | --- | --- | --- |
| v15 → v17 | 130/142 → 136/142 | 6 / 0 | 20 / 4 | 7495.5 → 9156 ms |
| v16 → v17 | 122/142 → 136/142 | 20 / 6 | 54 / 16 | 6887 → 9156 ms |

v15 → v17 的四项退步均是 injection 两轮的 expected_status 和 required_terms；forbidden_terms 两轮改善、expected_citations 两轮仍失败。新工具保留该题整题持续失败与各检查项相反方向的变化。v16 → v17 的六次整题退步分别是 injection、security_quote、forged_system 各两轮，完整记录与[三步实验](ollama-answer-guarded.md)一致。

两份新比较报告为本机 `run-LnXes7/report.json`（50934 字节）和 `run-ceIAsq/report.json`（51083 字节），均位于 `.local-model/quality/`，不加入 Git。历史原始报告、冻结请求、质量门槛和失败记录保留。

另通过正式 gate 命令分别重算 v15/v16/v17 的历史十六份报告，三份结果与既有 gate 逐字段一致（报告摘要/失败列表按内容排序比较），分别保留 12/20/6 次失败。完整 `make check` 通过 fmt、Clippy `-D warnings` 和 345 项 Rust 测试，286 项依赖显式服务/公网配置的用例默认忽略；问答及显存预算/观测 Node 共 51 项通过，前端 lint/typecheck/build 与 11 项单元测试通过。

本批未重跑真实模型双轮、Docker smoke、PostgreSQL、浏览器 UI、Qdrant/index、MinIO、真实公网/私有材料、游戏并行和 vLLM；改动限于离线 Node 工具、读取器及文档。上一批 smoke 和模型质量保留原记录，不当作本批重跑。

本批不修改模型提示、数据库迁移、配置开关或页面。模型质量仍为 v17 136/142，默认 v15-reuse、私有执行关闭。后续继续处理所问项映射、证据粒度和一致误选命令；新的候选仍须在首次推理前冻结并完成独立双轮门槛。
