# Sprint 3：显式测试回复页面

## 范围

对话消息下方提供回复历史、显式确认创建、状态轮询和取消。仅支持内置 `fixture`，不是模型生成，不调用知识库、长期记忆或付费供应商；默认禁用时仍展示历史和取消入口。发送用户消息不会自动触发回复。

新请求绑定当前成功读取的消息版本，创建前二次确认。没有消息、读取失败、已有未完成任务或累计 100 个请求时禁用新请求；最终版本和额度由服务端事务校验。每日次数与取消语义沿用[回复协议](sprint-3-model-replies.md)。

## 请求与恢复

- 每次新请求生成 UUID；失败保留原始版本与 ID，仅点击“重试回复原请求”才重发。未确认期间禁止发送消息、切换/删除对话，可刷新历史核对或显式取消已出现的请求。
- 放弃未确认请求需再次确认；这只清理本地状态，不撤销后台任务。完整刷新或退出会丢失本地 ID，但服务端回复列表仍可恢复已接受的请求。再次创建前须先核对历史，不把响应丢失当作执行失败。
- 仅当列表包含 queued/dispatching 时每 2 秒读取一次，终态停止。读失败保留旧数据显示并标注可能过期，停止轮询、禁用新请求，等待手动刷新；不把故障显示成空历史。
- 取消只发送显式请求，失败可手动重试或刷新核对；已完成任务不能撤销。unknown 明确提示不会自动重发，新请求会占用新额度。
- 切换对话、删除或退出时卸载面板，取消读取并忽略晚到响应。后台任务不因页面卸载而取消。所有私有状态仅在组件内存中，不存入 localStorage。

## 展示与后续

显示消息版本、请求 ID、六种任务状态和明确的“非模型生成”标记。回复始终按纯文本呈现，长内容换行并限制历史区高度，不执行 HTML 或 Markdown。

先验证真实服务下的显式请求、刷新恢复与桌面/移动布局，再补充响应丢失、取消、轮询停止、账户隔离及晚到响应的交互验收。真实供应商接入仍以模型专用费用预留和结算设计为前置条件。
