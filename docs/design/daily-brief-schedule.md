# 每日定时日报

用户在 Daily Brief 面板中显式启用并选择 UTC 时间，Scheduler 每天从已保存的 RSS 条目生成一份规则日报。默认没有配置、默认不执行；不访问 RSS 来源、不调用模型、不发送通知。自动 RSS 采集是独立的未完成项。

## 配置与接口

追加 `0028_brief_schedules.sql`。`feed_brief_schedules` 按用户保存配置版本、启用状态、UTC 分钟（0–1439）、下次计划时间和最近处理结果；删除用户时级联删除。配置版本及毫秒时间在 HTTP 中使用十进制字符串。

- `GET /api/feed-brief-schedule`：当前用户配置；无记录返回禁用、版本 `0`、默认 `09:00 UTC`。拒绝未知查询参数。
- `PUT /api/feed-brief-schedule`：`revision` 字符串、`enabled` 布尔值、`minute_utc` 整数、`acknowledge_schedule` 布尔值。启用必须明确确认；拒绝未知字段。要求会话及 CSRF 头，管理令牌不能代替用户会话。
- 保存采用用户锁和版本比较。当前版本或恰好前一版本的相同设置可以幂等返回已保存状态，不推迟下次时间；旧请求不能覆盖之后的停用或变更。
- 首次启用或改变时间从严格晚于数据库当前时间的下一个时刻开始。当天已经处理过自动任务时，新设置也必须等到次日。
- 成功响应 `no-store`。页面遇到不确定保存结果时冻结编辑，要求刷新核对，不自动重新提交；退出/会话失效清除配置，迟到响应不能进入另一账户。

示例：每天 18:30 UTC（北京时间次日 02:30）。

```json
{"revision":"0","enabled":true,"minute_utc":1110,"acknowledge_schedule":true}
```

停用不会删除已经生成的日报；历史仍通过现有日报接口查看。最近结果为 `generated` 时保存日报请求 ID，为 `skipped` 时不保存私有错误或正文，页面提示检查额度/条目限制。

## 执行与并发

部署者先完成 API 数据库迁移，再运行现有 `SCHEDULER_MODE=local` 的 scheduler。`disabled` 模式保持不连接数据库；`RUN_FOREVER=1` 时持续处理。没有新增环境变量，Redis 和对象存储不是执行依赖。

每轮先执行一次性提醒，再最多处理 100 个到期日报配置；无任务时等待，不扫描正文。选择任务时先锁用户并跳过被其他事务锁住的用户，与偏好变更、手动生成、停用及用户删除遵守同一锁顺序。

配置复核、读取当前关键词、生成不可变日报、来源关联、保存结果及推进下次时间都在同一个 PostgreSQL 事务中完成。数据库错误回滚全部内容，下一轮可再次尝试，不留下半份日报。多个进程竞争或提交回执丢失不会重复生成已提交的当天日报。

日报使用执行开始时的数据库 UTC 日期和时钟，最多尝试一次/用户/UTC 日，仍计入现有每日 10 份、累计 1000 份及最多 500 个候选条目的限制。达到配额或输入限制时，回滚生成保存点，记录 `skipped` 并推进次日，不持续重试或阻塞其他用户；用户仍可在条件允许时手动生成。空候选可以生成明确为空的日报。

进程停机后不补过去日期：若今天的设定时刻已过，恢复后生成今天一份；若尚未到今天时刻，只重新安排今天的执行时间。当天自动生成的日报即使被删除、失效，或定时配置被停用后再启用，也不会自动复活或生成第二份。

停用若先获得用户锁，则阻止之后的任务；生成若先获得锁，则可完成本次，随后停用停止未来执行。日志只记录处理数量及通用错误，不包含关键词或日报正文。调度器不执行迁移，缺少迁移必须由部署流程补齐。

## 验证

数据库测试覆盖默认关闭、版本冲突与原设置重放、跨用户隔离、事务失败全回滚、并发只生成一次、删除后不复活、锁跳过和每日配额满时跳过。真实进程测试同时验证一次性提醒和日报的禁用、执行及重启幂等。

HTTP 测试覆盖会话/CSRF、明确同意、严格输入、字符串版本与毫秒时间和账户隔离。双入口 Playwright 覆盖保存丢失后的查询恢复、刷新持久化、停用、会话失效以及迟到响应隔离。

本次验证通过 Rust 1.99 的 `make check`，前端 lint、typecheck 与生产构建，以及完整 `make browser-test`：134 项 PostgreSQL 测试、真实 scheduler 进程和 HTTP 验收通过，浏览器 86 项通过、8 项可选索引/公网用例按配置跳过。已检查桌面和移动端定时设置截图；隔离测试容器与数据已清理。
