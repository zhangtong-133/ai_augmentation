# Sprint 3：对话归属与元数据 API

## 范围

新增 `0010_conversations.sql` 和 `ConversationStore`：PostgreSQL 持久化用户归属、标题、创建请求 ID、创建时间及删除墓碑。API 启动时迁移，无新增配置。本文描述元数据接口；后续已交付[持久化用户消息与 Redis 快照](sprint-3-messages.md)及[管理页面](sprint-3-conversation-ui.md)。不调用模型，不把对话 ID 当作登录凭据。

## 协议

全部接口需要有效 Cookie 会话，写操作需要 `X-Requested-With: personal-ai`，管理 token 不替代会话。Next.js/Nginx 双入口可用，成功响应 `Cache-Control: no-store`。

| 请求 | 结果 |
|---|---|
| `POST /api/conversations`，`{"request_id":"UUID","title":"学习计划"}` | 200；首次与相同请求重放均返回同一记录 |
| `GET /api/conversations` | 200；当前用户未删除记录，按创建时间/ID 倒序，最多 100 条 |
| `GET /api/conversations/{id}` | 200；当前用户的未删除记录 |
| `DELETE /api/conversations/{id}` | 204；墓碑保留期间重复删除仍成功 |

记录仅返回 `id`、`title`、`created_at_unix_ms`，不返回所有者或创建请求 ID。对话 ID 由服务端生成；请求 ID 为客户端生成的 UUID，用于创建重试，不是对话身份。标题 1–80 Unicode 字符，不得全为空白或含 NUL；创建拒绝额外字段，包括客户端用户 ID。

未登录/撤销会话 401；CSRF 403；无效参数 400，结构不符可为 422；不存在、已删除或非本人读取均为 404，非本人删除也为 404。相同请求 ID 携带不同标题、重放已删除请求或额度不足返回 409。存储故障返回 503，不伪装成空列表。

## 幂等、额度与删除

- 请求 ID 在用户内唯一。事务锁定用户行，串行处理创建、删除及额度检查；同一请求并发创建不产生重复记录。先校验重放，再检查额度，已有记录可在满额时重试。
- 每用户最多 100 个未删除对话；滚动 24 小时最多创建 100 个新对话。删除不返还创建额度，重放不消耗额度，API 重启不重置。此处是持久化业务额度，不是覆盖所有接口的每秒请求限流。
- 删除清空当前标题、标记删除时间，保留 ID/归属/请求 ID/时间元数据；重复删除不延长墓碑。至少保留 24 小时，之后在该用户下一次成功创建事务中清理，没有后台定时清理。
- 未删除记录的创建幂等持续有效。墓碑清理后旧请求 ID 可重新创建**新的对话 ID**，因此客户端不得跨越删除后 24 小时无限重试；重复删除在墓碑清理后返回 404。数据库备份仍遵循部署方保留策略。
- 对话归属用户，而非某次登录。退出/重置密码使旧会话失效；同一用户重新登录可访问未删除对话。删除后开始的读取不能访问记录，但删除前已开始的读取可能返回旧快照。
