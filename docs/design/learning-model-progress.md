# 学习核验运行时增量通知

在[内部流式协议](model-streaming.md)之上，把订阅文本增量接到一次性学习核验执行器。新增接口是内部 Rust 通知端口，不是网页发送或读取端点；不新增迁移、持久化文本副本、后台执行器或真实模型调用。

## 调用及事件绑定

`observe_model_review(store, runtime, owner, request)` 返回有界 `Receiver<ReviewProgressEvent>` 与尚未启动的执行 future。调用者自行驱动 future 和消费 receiver；仅创建二者不领取授权。原 `execute_model_review` 入口复用该路径并丢弃 receiver，返回行为保持兼容。本机 `learning-run` 不新增终端增量打印选项。

事件的 owner、request_id 和从 0 连续递增的 sequence 全由执行器填写；供应商只能提供 Delta 正文，不能改变用户或请求绑定。事件类型不可序列化，也不包含凭据、派发 token、输入材料或供应商错误详情。Delta 是尚未校验的模型输出，可能包含其引用的私有材料，不能直接当作建议、分数、用户操作或日志。

正常路径为 Verifying → Sending → Delta（零条或多条）→ Persisting → Finished(status)。Sending 只在持久化发送标记成功之后发出；Finished 只在仓储完成来源复核、领域校验及事务保存返回之后发出，status 可能为 succeeded、unknown、cancelled、invalidated 等，不能把 Finished 一律视为成功。重复执行或无法领取发 NotClaimed，不返回旧建议，也不重新调用模型。仓储错误尽力发 StorageFailure，提示查询原请求，不承诺事务没有提交。

不支持增量的运行时沿用默认 `review_observed`，只产生阶段和终态事件，不伪造文本增量。订阅 SSE 只在解析并接受文本 delta 后通知；Unicode 拆包和传输失败仍由原适配器处理，完整结果继续等待正常 EOF 和领域校验。

## 有界通知与执行独立

队列容量为 16；一轮通知最多接受 24 KiB UTF-8 文本和 16384 次 delta。每次发送使用 `try_send`，不等待消费者。队列满、消费者关闭、正文或事件超限后永久关闭该通知通道；已排队事件可能仍被读出，但之后不会重新建立队列或补发终态。原模型执行继续，仍按原授权和发送标记保存完整结果；通知额度不是推理额度上限。

消费者必须按 owner/request 核对绑定与连续序号。收到 Persisting、Finished、NotClaimed 或 StorageFailure 时清除临时文本；遇到缺号、通道 EOF 而未收到终态、会话失效、来源撤销或账户切换，也必须清除。终态丢失时通过原私有查询读取持久化状态，不因通知丢失重发模型请求。不要把所有事件存进无界日志或队列。

丢弃 receiver 只关闭通知，不取消推理。丢弃执行 future 会停止本地等待并关闭通知通道，但已开始的供应商请求可能仍消耗额度；原 claim 和 sent 标记继续保留，业务读取超时后恢复为 unknown，不能重新领取。没有新增独立持久化取消入口，用户授权取消仍走原仓储。

**授权边界**：这个内部通道只供已经持有执行器权限的调用者使用，不提供新的访问授权，也不会对每条 delta 查询数据库。网页订阅必须另行校验会话、用户、请求和来源有效性，并在撤销/退出时关闭和清空临时视图；在这层保护完成前不能把内部通道直接暴露到 HTTP。

## 验证与后续步骤

纯通道用例覆盖容量、绑定、连续序号、断开、超限和唯一终态。SSE 用例覆盖逐字节 Unicode 增量、排除供应商元数据及错误后不再通知。本地账户运行时验证锁定账户及增量转发。数据库用例覆盖保存后终态、模型失败后的 unknown、重复执行不发送、满队列/断开仍可保存、丢弃执行 future 后不恢复授权，以及保存失败无成功通知。

下一批分步推进：

1. 定义版本化私有事件协议及订阅生命周期，明确本机执行进程如何与 API 通知进程衔接。运行时通道是进程内对象，不能假定网页进程能直接读取本机 CLI 内存。
2. 实现有权限复核、来源撤销和过期清理的事件读取入口；只读订阅不能触发模型执行或重放。验证跨账户、断开、代理缓冲和慢消费者。
3. 接入临时文本页面与最终建议查询，执行双入口浏览器故障验收；再推进独立本地模型适配、部署和备份恢复。真实订阅可用性及质量由用户单独验收。

## 本批验证结果

Rust 1.99 全仓格式、Clippy 和测试、前端 lint/typecheck/build 均通过；162 项 PostgreSQL 仓储、27 项学习 HTTP（含 4 项新增通知生命周期测试）、10 项学习运维数据库测试、Rust 1.96 生产镜像构建、核心 HTTP smoke 与 36 项学习双入口浏览器用例通过。一次性容器、网络和数据卷已清理。

另外根据 1acfa90 CI 日志修复两个权限夹具并发更新 PostgreSQL ACL 目录的竞争；以 16 个测试线程连续复验 10 轮运维套件均通过，详见[运维 CI 修复](sprint-4-learning-operations.md#权限夹具的-ci-并发修复)。完整 CI 由本次推送触发。未调用真实模型，本地未重跑其他页面全量、对象存储/向量专项或公网验收；没有 UI 实现变更。

后续已增加[私有状态事件接口](learning-status-events.md)：CLI/API 通过既有 PostgreSQL 状态实现跨进程观察，持续复核会话和来源。该通道只传状态；本文临时文本通道仍为同进程能力，未提供跨进程正文转发或页面展示。
