# Sprint 3：模型检索规划与两阶段费用授权

## 当前交付

`personal-ai-agent-core::model_plan` 已提供纯规划模块，版本为 `model-knowledge-search-v1`：有界用户消息上下文、严格模型建议解码、规划/执行两次独立报价、精确授权检查及用户日金额/次数检查。`budget::CostReservation::quote_input` 支持仅收取输入 token 费用的向量化调用，沿用整数算术、独立向上取整和保守结算。

初始纯模块交付没有接入模型、HTTP、页面或数据库。后续已落地[第一阶段规划请求仓储与事务预算](sprint-3-model-planning-store.md)，[第二阶段预算仓储](sprint-3-model-execution-store.md)也已实现，检索证据与模型执行仍待接入。现有 `knowledge-search-v1` 固定计划及其页面继续使用已有次数授权；本模块不改变它们的协议，也不使现有 Embedding、问答或部署全局费用自动受控。

## 两次明确确认

模型规划本身需要付费，因此不能先调用模型再请求首次授权。

1. 服务端从当前用户所属对话读取持久化快照，固定消息版本及配置，为**一次规划聊天调用**创建报价。用户确认指纹、币种、预留金额和调用次数后，未来仓储必须原子预留并一次性领取，才允许发送。这个授权不包含检索或回答。
2. 模型返回的查询仅是建议。服务端解码并保存，展示完整查询、顺序、片段上限及新的费用报价；用户再次确认后，才允许最多三次只读检索和一次回答。第二阶段不重复扣除规划预留，但日账本必须包含之前的规划支出。用户拒绝建议不能撤销已经发送的规划调用。

第一阶段次数为 `chat=1, embedding=0, tool=0`。第二阶段有 N 个查询时为 `chat=1, embedding=N, tool=N`，N 为 1–3；模型日次数包含聊天和向量化，工具次数另行限制。因此完整流程最多两次聊天、三次向量化、三次工具调用。失败、超时或结果未知的已派发尝试仍占次数，不通过新阶段或配置版本重置。

每个阶段的金额上限独立配置和确认，不把首次规划确认当作后续执行授权。首次规划金额和第二阶段金额之和才是整次流程的最大累计预留，页面接入时需展示这一关系。

## 模型输出与上下文

规划上下文复用显式回复的快照验证和最新连续后缀选择：快照最多 100 条用户消息，选取最多 16 条、包含系统提示最多 16 KiB UTF-8；不截断单条消息。已删除、空对话、版本不匹配、序号不连续或非法旧消息均拒绝。规划系统提示单独计入字节上限，输出硬限制为 2048 token。这里的字节数仅限制内存，不能作为可计费 token 数。

`model_search_schema()` 提供严格结构，适配器必须把它包含在冻结请求及计数中：

```json
{"searches":[{"query":"检索问题","limit":5}]}
```

模型只能返回 1–3 个查询，每条必须显式包含 `query` 和 `limit`。查询最多 1000 个 Unicode 字符，不能空白、含 NUL 或在去除两端空白后重复；limit 为整数 1–5。解码最多接受 16 KiB，拒绝无效 UTF-8、Markdown 包裹、额外正文、未知/重复字段和不完整结构。工具固定为 `knowledge_search`，模型不能选择其他工具、传入用户身份、价格、额度或批准字段。

严格 JSON 不证明查询有用或能抵御所有提示注入。消息、建议和检索结果始终视为不可信资料；身份、工具及权限取自服务端。当前模块不生成回答，后续回答输入应使用经归属复核的有界证据，明确资料不足并校验引用，不能保存模型提取的记忆或执行资料中的命令。

## 费用与指纹

金额使用币种百万分之一的整数单位。聊天使用已有公式：`ceil(input_bound × input_price / 1_000_000) + ceil(output_bound × output_price / 1_000_000)`；向量化仅计算输入部分，要求输出价格和输出上界均为零。每次向量化分别向上取整，然后与回答预留相加，避免将多个调用合并后低估计费舍入。价格和输入上界必须为正，拒绝 BIGINT 溢出、阶段超额及币种混用。

服务端 `ModelCallBudget` 冻结供应商、固定模型、配置/价格/计数器版本、币种、价格、完整输入/输出上界和价格有效期。规划输出上界必须等于 2048，回答必须等于 1024；向量化输入上界须对任何允许的单条查询成立，回答输入上界须覆盖原对话和最多 3 × 5 个有界片段。纯模块只检查这些数据的一致性，无法证明供应商计费契约、模型版本稳定性或计数规则。

供应商适配器接入前必须证明 schema、系统提示、角色封装、证据及所有计费输出均在上界内；固定请求费、其他模态、无法限制的隐藏输出或不明计费项均拒绝。派发前仍须对实际完整请求重新核验，不能把本次纯报价当作发送资格。没有内置市场价格；测试价格和 token 上界只是算术夹具。

报价指纹绑定版本、阶段、用户、对话、请求 ID、消息版本、上下文、schema、预算配置、阶段/日上限、精确金额、分类次数及到期时间。执行报价还绑定首次规划指纹和全部有序查询。更改任一价格、配置、查询、片段上限、顺序或身份都会使原确认失效。报价最多有效五分钟，且不能晚于任何本阶段价格配置的有效期；到期、消息版本变化或确认不精确时拒绝。

`AgentQuote::reserve_against` 同时计算金额、聊天/向量化总次数和工具次数的新占用值，包含未派发预留及已登记尝试。调用者必须在用户/币种/UTC 日锁内读取、检查、写入，防止并发超额。返回值只是纯计算结果，没有防重放、原子预留或执行权限。

## 下一步持久化协议

两阶段预算仓储已实现；下一步实现检索证据保存及回答协议，再实现经过计费验证的单次供应商适配器、内部执行器和页面。完整接入必须满足：

- 创建/批准/领取按用户→对话→日账本顺序锁定，核验归属、未删除、消息版本、精确指纹、价格有效性和持久化停用；提交未确认时禁止外部发送。
- 每阶段授权和每个付费派发都有持久化一次性 ID，同键重放返回原记录；进程重启、失败和未知结果不自动重发。规划结果不能仅凭客户端提交进入第二阶段，必须属于已完成的原请求。
- 同币种金额与已有付费回复共享用户 UTC 日占用，Agent 模型次数覆盖聊天和向量化；工具调用继续共享现有日审计，不因为预留和领取重复计数，也不能新建配置后清空预算。
- 取消/删除阻止未派发步骤，释放尚未派发的预留；已经派发的未知结果全额保留，已登记尝试不退还。可信 usage 在冻结上界内才能按逐次价格结算；越界需持久化停用配置并人工核对。
- 供应商、SDK、HTTP 和代理自动重试关闭；每步一次性领取后才发送。现有知识检索适配器的单次发送和输入计数也需核验，不能只给现有工具套一个报价。
- 取消/删除清除查询、上下文、证据和回答正文；独立最小金额/次数凭据保留。退出或关闭页面不撤销已批准的后台调用。
