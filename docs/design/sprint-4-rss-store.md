# Sprint 4：RSS 订阅仓储与一次性采集事务

## 本步交付

personal-ai-storage::feeds 定义 FeedStore，PostgresStore 实现订阅管理、不可变预览、精确同意与一次性领取、结果写回、超时恢复和私有分页查询。新增迁移 0024_feeds.sql，建立 feed_subscriptions、feed_collections、feed_entries、feed_collection_audit。应用现有迁移入口自动建表，不需要新增配置；本步没有 HTTP 端点、采集后台任务、真实 RSS 网络请求或页面。

仓储复用[采集纯规划](sprint-4-rss-collection.md)和[受限解析器](sprint-4-rss-parser.md)。未来登录态入口负责从会话确定 UserId，并执行 CSRF 校验；内部仓储身份参数不能视为客户端的授权声明。MCP 凭据不获得订阅或采集权限。

## 订阅与数据隔离

订阅唯一键为 (user_id, id)，所有读写都带用户范围；同一个 UUID 可以由不同用户分别使用，不共享来源或条目。名称去除首尾空白后要求 1–120 字符且无控制字符，来源 URL 复用 HTTPS/443/DNS 域名语法约束。创建和修改都不联网。

创建使用调用方提供的非空 UUID：同 ID、同当前内容返回已有记录，不重复创建；不同内容或已删除 ID 冲突。修改要求当前 revision；名称、URL、启用状态任一实际变化都会递增 revision，无变化不递增。停用再启用仍产生新版本，旧预览不能重新使用。

删除是不可复活的墓碑：递增版本、停用、抹去订阅表的名称/URL，并在同一事务删除条目；已存在的采集计划和审计仍留作私有历史，其中不可变计划保留当时的来源 URL。删除订阅不是清除全部历史记录，未来页面应明确展示这一语义。删除用户由外键级联清除所有这些记录。当前不提供自动历史清理。

所有修改先锁 users 所有者行，采用统一的锁顺序，序列化该用户的订阅版本、额度、领取、写回和恢复。数据库另外用部分唯一索引保证每用户最多一个 running 请求。查询不触发领取、恢复或联网。

| 限制 | 已实现行为 |
| --- | --- |
| 启用订阅 | 每用户最多 50 个；新建和重新启用均检查 |
| 订阅总记录 | 每用户最多 1000 个，含停用和删除墓碑，避免无限创建 |
| 预览创建 | 每用户滚动 24 小时最多 100 次；取消不返还，相同请求读取不计次 |
| 已领取采集 | 每用户每 UTC 自然日最多 20 次；按 claimed_ms 计数，失败/未知均计次 |
| 在途采集 | 每用户最多 1 个；跨订阅共享 |
| 结果写回期限 | 领取后 60 秒；超时只允许进入 unknown |
| 列表 | 订阅、采集历史、条目每页 20 条，取第 21 条判断后续页 |

订阅和历史游标按 UUID 排序，条目游标按身份键排序，不使用不可信来源日期分页。按请求查询审计最多三条（预览、领取、终态）。[执行器](sprint-4-rss-executor.md)另已实现进程内最多两个并行请求；数据库每用户限制与进程总并发限制分别生效。

## 一次性同意与执行凭据

preview_collection 从当前用户范围内读取订阅，由数据库时钟生成固定策略、5 分钟授权窗口和摘要，再将完整计划保存为 JSONB。重复 (user_id, request_id) 只返回原请求，不更新版本、来源或过期时间；同请求换订阅冲突。修改订阅之后，用户必须用新请求重新预览。

claim_collection 仅接收 owner、request_id、accepted_digest。事务加载已保存计划，核对记录主键与计划身份、当前订阅版本/来源/启用状态、固定策略、摘要及授权时间，然后检查额度与在途状态。精确同意和领取合并为一个事务，不保存可以再次领取的 approved 中间态：

- draft → running：持久化 accepted_digest、claimed_ms、60 秒截止时间和随机 claim_id，同时写 running 审计。提交成功后只返回一次 CollectionClaim。
- draft → cancelled：幂等取消，不能重新批准；取消不消耗采集额度，但预览创建仍计次。
- running → succeeded / failed / unknown：结果、审计和条目变化原子提交。
- succeeded / failed / unknown / cancelled 均不可重新领取。重复同意返回冲突，不能再次拿到凭据。

CollectionClaim 不提供反序列化或 Debug，查询结果不返回 claim_id。凭据绑定用户、请求、保存计划和随机令牌；伪造令牌、换用户或换计划不能完成写回。它只交给未来内部执行器，不能暴露成接受客户端执行结果的 API。

领取提交响应丢失时，调用方只能查原请求状态；不重新派发网络请求，也不通过重复确认取回凭据。运行中任务不允许通过取消释放在途名额。recover_collection 由明确调用触发，只把超过 60 秒的 running 标为 unknown，不退款、不重新领取。调用方确认未知状态后如需再次采集，必须创建新的预览并显式同意。

## 原子写回与审计

finish_collection 接收原始响应字节或固定失败类别。响应在事务外用受限解析器校验，不接受调用方拼装/修改过的条目，也不保存原始 XML。解析失败记录 failed/parse，不返回半批条目。传输失败记录 failed/transport；执行器无法判断网络结果时记录 unknown/unknown。

写回事务再次核对 claim_id、保存计划、running 状态与截止时间，并读取当前订阅。URL/名称/启用状态版本变化或删除先提交时，旧结果以 failed/subscription_changed 终结，条目不写入；已超时则以 unknown/execution_expired 终结。若写回先获得锁并提交，随后删除仍清除条目，不能复活已删除订阅。

条目使用 (user_id, subscription_id, entry_key) 主键。新身份新增；同身份同内容只更新 last_seen_ms；同身份内容变化更新正文及 updated_ms，保留 first_seen_ms。计数分别为 inserted、updated、unchanged。全批 upsert、计数、终态和审计必须一起提交，任何 SQL 失败全部回滚。未出现在本批的历史条目不会自动删除。

相同凭据重复写回已经完成的请求，只返回已保存终态，不改结果、不重复写审计，也不联网。事务结果未知时先查询原请求；不得更换 ID 自动重试采集。

审计表只保存用户/请求关联、事件、服务端时间、固定原因和计数，不包含完整来源、正文、GUID、claim_id 或原始 XML。计划、订阅及条目仍是私有数据，不自动 Debug 输出；数据库错误沿用脱敏错误信息。

## 验证与后续

新增 PostgreSQL 集成测试验证账户隔离、幂等请求、不可变预览、错误同意/过期/篡改拒绝、并发一次性领取、跨订阅共享额度、启用订阅并发上限、分页、删除竞态、超时未知恢复、原子更新/去重及审计故障回滚。使用本任务独立 PostgreSQL 16 临时容器运行完整 make test-postgres，完整 PostgreSQL 回归 100 项（含新增 9 项 RSS 测试）全部通过；make check、前端 lint/typecheck/build 均通过。

本步未运行 Compose HTTP smoke 或浏览器验收，因为未新增 HTTP/页面/联网行为；没有向外部订阅发送请求，也没有调用付费模型。

具备 DNS 公网校验、连接固定、禁止重定向/代理/重试、8 秒总超时和 1 MiB 流式上限的 [RSS 传输适配器与一次性执行器](sprint-4-rss-executor.md)已作为内部库实现。下一步接入会话/CSRF 保护的 HTTP 管理和订阅页面。自动轮询、价值评分、Daily Brief、条件请求和原文抓取均未实现。
