# 学习核验临时正文流式展示

目标：将本机显式执行的学习核验增量送到当前用户网页。模型授权、一次领取/发送、严格最终建议保存及人工确认继续复用既有协议。观察入口只读，不能触发执行。

## 分阶段交付与验收

1. **临时跨进程通道**：供应商无关端口、Redis Pub/Sub 适配、本机 learning-run 转发；验证 Unicode 分段、归属/序号、容量、断开、无回放及通知失败不重发执行。
2. **私有正文接口**：有期限 GET 事件、持续会话/授权/连接/证据复核、共享连接限额、双代理转发；验证真实跨连接发送、注销/撤销/删除、故障和资源释放。
3. **页面与集成验收**：显式观察当前临时文本，纯文本展示，清除与最终建议查询分离；严格解析、停止/退出/切换/截断/晚到保护，双入口桌面/移动验收、截图及固定学习验收。

各阶段通过验收后独立提交推送。后续为独立本地模型适配、部署与备份恢复、完整回归及真实订阅质量验收。本批不调用真实模型。

## 通道边界

API 与 CLI 使用同一可信 Redis 的 `LEARNING_TEXT_REDIS_URL`；未设置/空值默认关闭，不借用聊天缓存开关。只使用 Pub/Sub，不创建键、不存入 PostgreSQL/Redis Stream，不保留正文或补发历史。Redis 即使启用 AOF 也不会存储 Pub/Sub 消息。Redis 是可信服务端数据边界，不能向浏览器暴露地址、密码或连接凭据；频道哈希不是访问控制，部署者须限制 Redis 访问及 Pub/Sub ACL。

每个频道绑定用户和请求 SHA-256；内部信封仍校验版本、用户、请求。临时正文每段最多 512 UTF-8 字节，每次执行累计最多 24 KiB、1024 个包；序号连续。新观察可从中间序号开始，只展示当前连接收到的后缀，不承诺完整答案。Clear 后不得再发正文，End 只结束通知，不能表示建议已保存。

接收应用队列最多 16 个包，20 秒后关闭；断开或溢出不回放、不重连，丢弃未消费包，Drop 取消接收任务。Redis SDK 内部有独立接收队列，可信发布者的总量限制约束它，应用层限额不宣称能阻止拥有 Redis 权限的恶意发布者。Redis 故障/消费太慢只关闭临时通知；原执行及其单次发送标记保持有效，终态仍从原私有 JSON 接口核对。

CLI 在已有精确授权和本机账户验证路径中使用桥接，不新增自动执行入口。每个原始通知先核对执行器的用户、请求和连续序号；仅 Delta/Clear/End 出桥接，凭据、输入提示词、执行令牌、原始错误及终态状态不转发。桥接建立或发送失败不重试，也不重发模型。
