# 用户证据核验与显式自评确认

## 边界

本阶段保存用户逐项核验及其显式确认，不调用模型，也不生成建议分数。它是证据到自评的可追溯闭环，不代表已经完成模型能力评估或客观能力认证。

量表 `user-evidence-review-v1` 包含概念解释、独立练习、结果验证、局限与反例四项。每项由用户选择 `missing`、`unverified` 或 `supported`，并填写 1–500 字、最多 2000 字节的理由。拒绝空白、未知字段/状态和除换行、制表符外的控制字符。全部 supported 也不自动产生分数；理由和证据是否真实仍需用户判断。

## 保存与确认

新增迁移 `0037_learning_reviews.sql`，一份证据至多保存一份不可变核验，绑定 owner、任务、证据请求 ID 和量表版本。来源必须仍有正文，首次保存时技能须启用且版本与原任务一致。重复同请求同正文返回当前记录，改变内容或请求则冲突。缺少证据或待核验的记录可以保存，但不能据此确认评分；补充材料需新的训练与证据。

`POST /api/learning/plans/{plan}/tasks/{task}/evidence/review` 接收 `{request_id, evidence_request_id, body}`。保存仅产生 pending 核验，不修改自评和学习版本。

`POST /api/learning/plans/{plan}/tasks/{task}/evidence/review/confirm` 接收 `{request_id, review_request_id, expected_revision, score}`，其中学习版本沿用精确十进制字符串，分数为用户主动填写的 0–100 整数。服务端重新检查来源有效性、四项 supported、当前学习版本、技能版本及启用状态，并复用自评额度与写入逻辑，在 owner 事务锁内一次性写入自评和 confirmed 状态。评分记录 ID 由服务端生成。旧学习版本拒绝；刷新后可再次审阅并以新版本明确确认。技能已变更则旧证据不能用于新版本。

已确认记录只接受原确认请求、原分数和原预期版本的幂等重试；不会重复写入自评，也不要求重试使用已经递增的学习版本。不同请求或内容冲突。多条核验同时确认同一快照时，仅第一条成功；其他确认不能静默覆盖。

两条路由要求会话与 CSRF，严格校验输入，响应 no-store，返回当前计划。Next 代理只放行这两个 POST 路径，沿用 16 KiB 请求上限。核验随 `results[].evidence.review` 返回，包含来源/请求/量表、状态、可空正文与确认关联，不复制原证据全文。

## 来源删除

软删除证据会把核验置为 invalidated，清除全部核验理由及显示分数，并将它关联的自评 score 置空；若撤销了自评，同一事务递增学习版本。重复删除不再次递增。原始训练备注和其他独立自评保留，因此删除后可能回到更早的有效自评。

删除计划、来源技能或账户时，外键和证据删除触发器执行相同的撤销与清理；来源正文清除后不能重试恢复确认。普通技能修改保留历史核验和当时自评，但新技能版本不会使用旧评分。

## 页面

证据正文下提供逐项判断及理由，保存前二次确认。已保存记录明确标注为用户判断，不是模型评估。仅全部 supported 且技能版本可用时显示空白分数输入框，用户填写并二次确认后才产生自评。删除证据前明确说明核验与关联自评也会清除。

复用学习面板的原请求重试、刷新、会话失效、账户卸载与晚到响应保护。正文按纯文本展示，不处理 HTML 或外部链接。

## 历史计划的只读来源标记

撤销自评后，以该分数生成的后续计划保留历史快照、原始训练记录与独立材料，不自动扩大删除范围。计划详情新增实时计算的 `source_assessments_available`：逐项核对快照引用的自评是否仍可用；为 false 时阻止新增训练结果、证据、核验及未完成的确认。已保存操作的相同请求重试仍可核对既有结果。历史计划仍可查看或由用户明确删除，待记录训练统计排除来源已撤销的任务。

页面明确标注历史分数来自已撤销自评，并提供原有删除计划入口。后续独立训练及其已确认自评不会因为早期证据删除而自动撤销。本实现没有加入后续计划的级联删除迁移。

后端验收：Rust 格式、Clippy、工作区测试通过；10 个真实 PostgreSQL 学习 HTTP 用例通过，覆盖严格输入、用户隔离、CSRF、并发幂等、单项待核验拒绝确认、学习/技能版本冲突、删除竞争、四类来源清理、独立自评保留，以及历史计划保留与新增写入保护。
