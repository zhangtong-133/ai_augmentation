# 已完成订阅评分的私有阅读

已完成评分可通过 `GET /api/feed-values/{id}/reading` 读取同一批候选的阅读投影。没有数据库迁移、额外内容副本或新模型调用，也不改写规则日报和定时日报。候选必须来自原评分冻结快照，不能混入当前采集结果。

## 数据与顺序

响应含 `id`、`digest`、`status: succeeded`、字符串时间 `day_start_unix_ms` / `as_of_unix_ms`、冻结关键词 `keywords`，以及 `items`：

- `id` 是原规则候选的 1 起始名次，也是模型评分临时编号。
- `title`、`summary` 和可空 `link` 取自原候选；link 是文章链接，不是订阅地址。
- `rule_score` 保留原规则分数；`model_score` 是 0–100 或 null，`reason` 为模型理由。两种分数不可混作同一标尺。

服务端重新构造可信评分计划，并复用严格返回协议校验存储评分的完整覆盖、唯一编号、分数和理由。列表按模型分数降序，null 最后，同分按原规则名次；客户端切换规则排序仅按 id 升序排列，不修改数据。

输出显式列举字段，不返回用户身份、来源订阅地址、数据库条目键、派发凭据或原始模型响应。客户端应以纯文本展示标题/摘要/理由，并独立校验链接，仅在用户点击后打开，不预加载外部资源。

## 生命周期与私有性

所有权从会话取得，跨用户和不存在为 404，未登录为 401；拒绝所有查询参数。仍复用原评分仓储的锁、到期回收、摘要校验和失效触发器。只有 succeeded 且内容/评分有效时返回 200，其他状态为 409 且无正文，已解码的存储评分未通过完整协议校验时为 503。所有响应 no-store。

来源/条目、偏好或连接变化会使原记录及正文失效。已完成评分不会仅因批准期限结束而消失，仍遵守原连接与内容生命周期。并发读取以仓储读取事务为准；页面在重新核对或相关本地修改时清除旧视图，跨设备变更需重新读取才能发现。

## 验收与交付

纯函数测试覆盖模型/规则排序差异、同分稳定排序、null 与零分、准确映射冻结正文/链接、最小输出和损坏评分整体拒绝。真实 PostgreSQL HTTP 用例验证未完成拒绝、已完成读取、身份隔离、未知参数、损坏结果、连接撤销与 no-store。双网关 smoke 使用已完成数据库夹具验证正文、映射与来源删除后不可读；真实一次性发送链路继续由原执行器测试覆盖。已接入评分详情的“读取评分阅读”入口。

第二步验证通过：11 个评分纯协议测试、Rust 全量 fmt/Clippy/测试、前端 lint/typecheck/build、完整生产镜像 smoke（含 162 个 PostgreSQL 测试和双网关阅读/删除失效），测试资源已自动清理。未运行真实模型；页面交互的第三步验收记录见下文。


## 阅读页面

评分详情仅在 succeeded 时显示“读取评分阅读”。读取完成后展示冻结摘要、原文链接、原规则名次和独立的两种分数；默认模型分数降序，可切换原规则名次，切换仅在浏览器内排序，不发网络请求、不持久化偏好、不覆盖日报。

阅读响应须匹配当前请求和 digest，并验证完整候选编号、标题映射、分数范围及有界文本；失败清除原详情与阅读正文。HTTP(S) 无凭据链接才显示“打开原文”，新窗口使用 noopener/noreferrer/no-referrer；无效链接不显示可点击入口，标题/摘要/理由均按纯文本渲染。

RSS 管理/采集、日报偏好保存、连接撤销在请求开始和结束时通知评分面板清除私有视图并终止等待，写入响应丢失也不会继续展示旧内容。未确认的评分写入 ID 仍保留，供显式核对；没有自动创建、批准或重发。跨设备变化仍需主动核对，页面不宣称实时同步。

新增双入口浏览器验收覆盖模型/规则顺序、null 与零分、安全原文链接、无额外模型请求、快照摘要不匹配、409/401 清理、真实偏好保存中止待返回阅读、账户切换与晚到响应隔离，并检查窄屏布局和截图。

第三步验证通过：前端 lint/typecheck/build、18 个评分/阅读定向浏览器用例，以及完整 `make browser-test`（162 个 PostgreSQL 测试、HTTP smoke、138 个浏览器用例通过，8 个可选索引/公网用例跳过）。已检查桌面/移动端截图；测试栈全部清理。没有运行真实模型或对象存储专项，规则日报行为不变。
