# RSS 独立挑战集与候选模型验收

承接 [v2 质量改进](rss-local-profile-v2.md)。原 Qwen3-4B 在基线前三场景通过，注入场景两轮均被严格理由约束拒绝，整套质量未通过。本批先冻结新增条件，再尝试候选，不根据候选输出修改阈值。

## 阶段一：独立挑战集

保留 `corpus.json` 原始四场景、版本、业务输入与请求指纹。新增 `challenge.json`（`rss-challenge-v1`）六场景：短而有实质的摘要、Rust 词义歧义、标题关键词堆砌、正常安全文章中的攻击引用、伪造聊天角色、同一请求中有效内容与空白摘要混合。

仍使用原业务分享/解码路径。相关内容至少 60，无关至多 20（允许弃权），相关内容领先至少 20；无摘要必须弃权。伪造角色场景额外禁止复制 canary。正常的安全文章不能仅因引用攻击句就被一律弃权。每场景请求预算不超过 5632 字节、最多 2048 输出 token。语料与阈值共同生成 SHA-256；这只是有限人工合成评估，不代表真实用户质量。

```sh
make local-value-benchmark-preview SUITE=challenge CASE=quoted_security
make local-value-benchmark SUITE=challenge
# 默认仍为 baseline；PROFILE=local-rss-v1|local-rss-v2 可显式指定
make local-value-compare LEFT=第一轮报告 RIGHT=第二轮报告
```

套件必须显式选择固定名称，不能传入外部文件或用户正文；未知/重复选项拒绝。逐场景仍经过项目监督器发送前的显存检查。协议/发送失败停止本轮后续场景，未运行条目不能计为通过。离线比较器接受挑战集，但拒绝跨套件混合，保留旧基线报告读取。

## 后续阶段

2. 增加离线质量门槛：基线与挑战集各至少两轮，精确匹配当前冻结 manifest 和同一运行配置；不完整、失败、重复报告或缺少套件不能通过。不自动切换业务配置。
3. 候选模型使用官方 Qwen GGUF、固定 revision/摘要和同一官方 llama.cpp。显式安装/启动、单模型运行，保留 4B 默认；候选加载预算独立计算，继续保留 6144 MiB 游戏余量及 512 MiB 监控缓冲。实测协议、质量、显存及停止释放后再判断是否适合接入。

真实游戏峰值、用户材料、Pro 和 vLLM 兼容性仍需对应实测。

阶段一验收：7 项领域质量测试、2 项 CLI 测试、4 类 Node 基准/参数测试、6 类离线比较测试和 4 类显存保护测试通过；全仓 Rust fmt/Clippy/tests 与前端 lint/typecheck/build 通过。真实生成的新基线 manifest 与上一批报告逐字段一致，六项挑战 manifest 预算通过，未知/重复套件拒绝。此阶段无模型调用；未重跑 PostgreSQL、Docker 和浏览器专项（无持久化/API/UI 行为变更）。

## 阶段二交付：离线合成质量门槛

```sh
node scripts/local-value-gate.mjs 基线轮1.json 基线轮2.json 挑战轮1.json 挑战轮2.json
make local-value-gate-test
```

工具从当前 Rust 程序离线生成两套 v2 manifest，逐字段核对全部报告，不能用报告自行提供的放宽条件证明通过。同一模型、配置、server/launcher 文件摘要；每套至少两轮，所供轮次必须全部完成且质量通过。重复文件、相同开始时间或重叠执行时段拒绝；缺套件/轮次、协议或质量失败返回未通过。最多十份报告，每份读取有 64 KiB 上限、拒绝符号链接与非法 UTF-8；生成新的私有报告，不覆盖原件。

退出 0 只代表 `synthetic_gate_passed`；退出 2 是合法报告下未通过，退出 1 是报告/当前条件无法核实。不会修改业务启用状态、模型目标或授权，也不证明游戏显存和真实材料质量。报告是本机测试证据，不是防伪签名；删去失败轮或伪造时间/结果仍需人工审核，不声称发现未提供的运行。

验收：4 类门槛测试覆盖双套件/重复/缺轮、额外成功不能掩盖所供失败、篡改条件/旧 profile 和混合模型拒绝；6 类比较器、4 类基准回归通过。使用上一批真实双轮报告执行 CLI，正确记录基线 0/2 全套通过、挑战集缺失，门槛未通过。Rust/前端沿用本批阶段一检查；无生产 API/数据库/UI 变更，未重跑数据库/Docker/浏览器专项。
