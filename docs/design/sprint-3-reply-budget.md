# Sprint 3：回复货币预算与供应商边界

## 本轮交付

`personal-ai-agent-core::budget` 提供纯费用规划：输入/输出分别向上取整、单请求上限、日额度检查、可信 usage 结算，以及未知结果全额保留。价格和 token 上界必须显式非零，金额使用整数微货币单位（币种的百万分之一），拒绝 PostgreSQL BIGINT 溢出。测试价格只是算术夹具，不代表供应商报价。

本轮没有接入 HTTP、执行器、数据库账本或真实模型；`CostReservation` 仅代表计算结果，不能作为发送授权。默认 `disabled` 和现有 `fixture` 行为不变，无迁移或新增环境变量。现有知识问答与 Embedding 不受此模块约束，不能声称部署全局费用已受控。

## 价格与计数边界

未来部署配置必须明确币种、每用户 UTC 日上限、单请求上限、供应商、固定模型版本、价格版本和计数器版本。每百万 token 的价格以整数微货币单位表示，不从客户端接受价格，不内置实际报价，不混合币种。币种变更必须使用独立账本且不能借配置切换重置同币种日额度。

适配器必须针对冻结的完整请求计算可计费输入上界，包含角色、消息封装、系统提示和供应商附加开销；现有 UTF-8 字节数不能冒充 token 计数。输出上限必须覆盖全部计费输出（包括供应商可能计费的隐藏推理），且由供应商硬限制。缓存按未折扣价预留。首版仅支持可以证明输入/输出两类费用上界的纯文本模型；工具、图片、固定请求费或其他收费项均拒绝。未知模型、浮动别名、未知计数规则或无法强制输出上限时禁止派发。

计算式为 `ceil(input_bound × input_price / 1_000_000) + ceil(output_bound × output_price / 1_000_000)`，输入/输出独立向上取整。乘法使用 u128，中间结果除法后求和，最终检查 i64。适配器负责验证供应商计费粒度与这个上界兼容；价格上调必须停用旧配置，不能只凭历史价格断言费用受控。

## 下一阶段持久化协议（尚未实现）

追加迁移，增加按用户、UTC 预留日期、币种唯一的金额账本，以及独立的请求预算记录。预算记录冻结供应商/模型、价格/计数器版本、币种、两个价格、输入/输出上界、预留金额、预留日期、结算金额和一次性结算标记。账本占用量等于未结算预留加已结算费用，不能仅统计成功回复。

创建沿用用户→对话锁顺序：先验证归属和同键重放，再冻结上下文并计数，在同一事务中预留次数和金额、插入请求。调用 `reserve_against` 时必须锁定对应日账本；纯函数本身无法防止并发超支。额度不足、计数失败或提交失败全部回滚。重放返回原请求，不使用新配置重新报价。领取前重新验证冻结配置仍被允许；提交确认后才允许发送，SDK/HTTP/代理重试必须关闭。

只在 queued 取消时一次性释放全部金额和次数，跨日退款落回原预留日。派发后取消、超时、崩溃、HTTP 错误或不可信 usage 均保留全部金额；这些情况不能证明未计费。完整且经过适配器核验的 usage 在冻结上界内时可以按冻结价格结算并退差额。`settle(None)` 表示全额保留；超上界 usage 同样全额保留，同时未来执行器必须告警、禁用配置并人工核对超额，不能宣称预留覆盖了实际账单。

终态重放不能重复退款，迟到结果不能覆盖取消/unknown 的结算。删除对话在同一事务内退回 queued 预留，派发后保留；金额账本和最小结算凭据不能随对话墓碑级联删除，否则无法审计和证明日额度。凭据不保存正文或密钥，用户删除及账本保留周期须在迁移落地时明确。

## 供应商启用门槛

1. 落地上述账本、原子预留和一次性结算；测试最后一份额度并发、同键重放、跨日退款、删除和崩溃恢复。
2. 实现固定模型计数器和单次发送适配器，核验超时、usage 缺失/越界、价格版本失效及输出上限。使用本地 HTTP 夹具，自动测试不调用付费模型。
3. 接入执行器及显式启用配置，在页面说明金额上限和未知结果可能已计费；双代理入口验证认证、CSRF、用户隔离和原请求重试。

完成这些门槛前，路线图的“货币预算与真实供应商适配”仍保持未完成。
