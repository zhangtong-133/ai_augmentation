# Sprint 3：回复货币预算与供应商边界

## 当前交付

`personal-ai-agent-core::budget` 提供纯费用规划：输入/输出分别向上取整、单请求上限、日额度检查、可信 usage 结算，以及未知结果全额保留。价格和 token 上界必须显式非零，金额使用整数微货币单位（币种的百万分之一），拒绝 PostgreSQL BIGINT 溢出。测试价格只是算术夹具，不代表供应商报价。

新增迁移 `0013_reply_money.sql` 和内部 `BudgetedReplyStore` 端口，已实现 PostgreSQL 金额账本、事务预留与一次性结算。`CostReservation` 本身仍只代表计算结果，不能作为发送授权。HTTP/执行器尚未调用预算端口，默认 `disabled` 和现有 `fixture` 行为不变，无新增环境变量。现有知识问答与 Embedding 不受此模块约束，不能声称部署全局费用已受控。

## 价格与计数边界

未来部署配置必须明确币种、每用户 UTC 日上限、单请求上限、供应商、固定模型版本、价格版本和计数器版本。每百万 token 的价格以整数微货币单位表示，不从客户端接受价格，不内置实际报价，不混合币种。币种变更必须使用独立账本且不能借配置切换重置同币种日额度。

适配器必须针对冻结的完整请求计算可计费输入上界，包含角色、消息封装、系统提示和供应商附加开销；现有 UTF-8 字节数不能冒充 token 计数。输出上限必须覆盖全部计费输出（包括供应商可能计费的隐藏推理），且由供应商硬限制。缓存按未折扣价预留。首版仅支持可以证明输入/输出两类费用上界的纯文本模型；工具、图片、固定请求费或其他收费项均拒绝。未知模型、浮动别名、未知计数规则或无法强制输出上限时禁止派发。

计算式为 `ceil(input_bound × input_price / 1_000_000) + ceil(output_bound × output_price / 1_000_000)`，输入/输出独立向上取整。乘法使用 u128，中间结果除法后求和，最终检查 i64。适配器负责验证供应商计费粒度与这个上界兼容；价格上调必须停用旧配置，不能只凭历史价格断言费用受控。

## 持久化协议（已实现）

`reply_money_daily` 按用户、UTC 预留日期、币种唯一；`reply_money_reservations` 保存独立的请求预算记录。预算记录冻结供应商/模型、价格/计数器版本、币种、两个价格、输入/输出上界、预留金额、预留日期、结算金额和一次性结算标记。账本占用量等于未结算预留加已结算费用，不能仅统计成功回复。

创建沿用用户→对话锁顺序：先验证归属和同键重放，再冻结上下文并计数，在同一事务中预留次数和金额、插入请求。仓储持有用户锁并锁定对应日账本后调用 `reserve_against`，账本不按供应商或价格版本分组，配置版本变化不能重置同币种已用金额。额度不足、计数失败或提交失败全部回滚。重放返回原请求，不使用新配置重新报价；旧的无金额请求也不会因改用预算端口而补扣款或升级为付费请求。服务端 `ReplyBudgetPlanner` 在事务内接收完整冻结上下文（含模型配置）并同步计数，只允许有界纯计算；仓储核验币种格式、配置标识、价格、额度和输出上界等于请求硬上限。已提供[固定快照正文计数及完整上下文窗口上界策略](sprint-3-reply-provider.md)，运行时尚未接入，测试仅使用显式本地夹具。

只在 queued 取消时一次性释放全部金额和次数，跨日退款落回原预留日。派发后取消、超时、崩溃、HTTP 错误或不可信 usage 均保留全部金额；这些情况不能证明未计费。完整且经过适配器核验的 usage 在冻结上界内时可以按冻结价格结算并退差额。`settle(None)` 表示全额保留；超上界 usage 同样全额保留，仓储记录 `usage_exceeded` 结算原因，未来执行器必须据此告警、禁用配置并人工核对超额，不能宣称预留覆盖了实际账单。

终态重放不能重复退款，迟到结果不能覆盖取消/unknown 的结算。删除对话在同一事务内退回 queued 预留，派发后保留；金额账本和最小结算凭据不能随对话墓碑级联删除，否则无法审计和证明日额度。凭据不保存正文或密钥，与次数账本一致保留至用户删除，届时级联清除；暂不自动归档。预算配置标识必须由服务端生成，不得包含凭据。结算记录保存金额、原因和时间，不保存供应商响应正文。

## 供应商启用门槛

1. 已落地账本、原子预留和一次性结算；覆盖最后一份额度并发、同键重放、重连、跨日退款、删除和派发过期恢复。
2. 已实现固定模型离线计数和单次发送适配器，使用本地 HTTP 夹具验证超时、usage 缺失/越界、配置不匹配及输出上限。配置停用当前仅在进程内有效，运行时启用前必须补齐持久化停用和价格有效性检查。
3. 接入执行器及显式启用配置；付费派发必须核验已提交的预算凭据和仍有效的冻结配置，不能仅凭 `Reply.context` 或现有无金额的历史请求发送。领取提交确认后才允许发送，SDK/HTTP/代理重试必须关闭。在页面说明金额上限和未知结果可能已计费；双代理入口验证认证、CSRF、用户隔离和原请求重试。

完成这些门槛前，路线图的“货币预算与真实供应商适配”仍保持未完成。
