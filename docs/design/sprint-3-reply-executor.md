# Sprint 3：预算回复供应商执行器

## 当前交付

`personal-ai-agent-core::reply_executor` 提供内部 `ReplySender` 端口及 `BudgetedReplyExecutor`，OpenAI 适配器实现该端口。业务执行器只依赖存储和供应商接口，应用入口负责组装。现有适配器的 `ReplyCompletion` / `ReplySendError` 从原模块重新导出，调用方式兼容。

此轮完成内部执行链及本地夹具验收。HTTP、环境变量和页面仍仅支持 disabled / fixture；尚未在应用启动时组装付费执行器，升级不会自动发送模型请求。下一步是部署配置、预留入口检查、页面金额说明与双入口交互验收。

## 执行流程

1. 按模型及配置版本扫描最多 20 个未结算金额请求，优先处理过期派发。扫描不受其他配置或无金额夹具队列占满影响。
2. 过期派发仅调用仓储过期收敛，绝不重新领取。queued 请求通过预算端口领取，提交失败或结果不明时不调用供应商。
3. 领取后复核过期、取消/删除状态及持久化配置有效性；检查失败不发送。已领取请求保守保留金额，终态或删除后不写入迟到输出。
4. 供应商每次至多发送一次，执行器另设 35 秒超时。已有 OpenAI 适配器仍使用 30 秒 HTTP 时限及无重试客户端；超时不会重新排队或重发。
5. 完整成功输出及可信 usage 交给一次性结算；缺失 usage 保留全额。网络未知、超时、非法响应或发送前配置拒绝也保留全额。结算写入失败不重发，保留派发状态，后续 120 秒过期恢复为 unknown。
6. 契约异常或执行器复核发现 usage 越界时，本实例立即停止发送，记录错误级告警，持久化停用配置，并将本请求收敛为 unknown。若停用写入失败，本实例继续关闭，后续 tick 只重试停用及过期恢复。

现有夹具执行器在领取前跳过其他配置，避免把真实供应商请求领取后标为失败。

## 并发与故障边界

并发执行器依靠数据库领取事务保证同请求至多一方获得凭据。取消、删除和迟到输出的冲突由既有仓储锁及终态规则处理。执行器不缓存或重用领取凭据，不在完成失败后重新生成。

最后一次数据库检查与网络发送无法形成单一原子操作；取消或停用不能撤回已经开始的网络请求。停用写入失败时，其他实例尚不能观察本实例的停用，本地停止和错误日志不能被描述为全局熔断。运行时开放前还需要部署监控与人工价格/账单核对流程。

执行器不会自动接受新价格、登记配置、接收用户价格参数或扩大额度。此前金额预留端口仍允许离线测试；正式创建请求入口必须额外检查有效配置。历史无金额请求不会升级为付费请求。

## 验证

真实 PostgreSQL 与本地 `ReplySender` 夹具覆盖：多实例只发送一次、可信用量退款、缺失用量/网络失败/非法响应全额保留、契约异常及越界用量停用、重连后拒绝停用配置、无金额请求拒绝、过期不重发、取消和删除丢弃迟到输出、35 秒执行超时、结算写入失败恢复，以及停用写入失败后本地停止并重试持久化。

测试故障通过仅匹配本测试请求/配置的临时数据库约束注入，测试成功后移除。所有模型调用均为本地夹具，不使用真实付费供应商。
