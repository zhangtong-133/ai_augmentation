# Sprint 3：模型规划请求仓储与事务预算

## 当前交付

已落地[两阶段费用设计](sprint-3-model-agent-budget.md)的第一阶段：固定规划配置登记/停用、报价预览、精确授权、金额和模型次数的原子预留、一次性领取、严格建议保存、结算、取消和到期处理。端口位于 `storage::model_agents::ModelPlanningStore`，PostgreSQL 适配器由应用入口按需组装。

本步只提供内部仓储，不增加 HTTP、页面、环境变量或模型发送入口。规划建议不会触发知识检索。下一步实现第二阶段检索/回答的预算与领取，再接入单次供应商适配器和执行器。

## 配置与冻结报价

新增迁移 `0019_model_planning.sql`。`model_planning_configurations` 登记完整固定预算、阶段/日金额上限、Agent 模型日次数、价格有效期和配置版本。相同版本只能完全相同重放，不能更改价格、上界或额度；显式停用不可逆，重新登记不能恢复。登记、预览、批准、领取及发送前检查使用数据库时钟和持久化配置。首阶段输出硬上限仍为 2048 token。

配置必须来自部署端审核过的适配器，不能接受用户提供的价格。仓储核验协议和预算一致性，不证明模型计费契约、输入计数或供应商输出限制；后续适配器仍须证明完整请求含 schema/封装的上界。

创建时按用户→对话加锁，核验对话归属、未删除及已有消息版本，读取最多 100 条持久化用户消息，使用纯规划模块生成报价。冻结完整快照、配置、版本、指纹、金额、创建时间和到期时间；快照 JSON 最多 3 MiB，覆盖 100 × 4096 字节正文在控制字符转义后的最坏扩张。有效期最多五分钟且不晚于价格失效时间。元数据响应不包含快照、内部价格、配置或领取凭据。

预览不预留金额或次数。每个对话最多保留 100 项请求，同时限制用户当日新预览与该对话历史的合并计数不超过 100，防止无授权预览无限增长。用户/请求 ID 唯一，同 ID 不能换对话、消息版本或配置版本。相同请求重放返回原记录，即使消息或运行配置后来改变，也不重新报价。

## 批准与账本

批准必须精确匹配原指纹、币种、金额、`chat=1/embedding=0/tool=0` 和主动费用确认，同时复核消息版本、配置有效性和报价期限。相同批准重放返回原状态，`started=false`，不能重新启动；不匹配的批准不扣款。取消后的批准不能重新激活请求。

批准事务同时写入以下记录，全部提交确认后才返回：

- `reply_money_daily`：复用已有用户/UTC 日/币种金额占用，包含付费回复及模型规划，配置或供应商切换不重置额度。
- `model_agent_daily`：本阶段一次聊天调用的占用，包含未派发预留和已派发尝试，独立于对话保留。当前只接入规划阶段；不能声称现有其他模型入口受这个次数账本限制。
- `reply_money_reservations`：复用独立金额凭据，新增 `request_kind` 区分 `reply` 和 `model_planning`，记录原预留日、模型、价格/计数规则及一次性结算。
- `model_planning_requests`：保存持久化精确批准，进入 `queued`。

额度不足、同键冲突、存储或 COMMIT 失败回滚整个预留，不产生可用授权凭据。新模型配置使用同一用户日次数及同币种金额，不能绕过已经占用的预算；其他币种金额独立，但 Agent 模型次数共用。用户日锁让两个并发请求不能同时拿到最后一份额度。

已更新回复的领取、扫描、金额查询和结算，仅接受 `request_kind='reply'` 的凭据，防止旧无金额回复以相同 ID 误领或退回模型规划预算。独立金额主键也阻止两个付费请求类型共用同一对话/请求 ID。

## 领取、完成与取消

状态包括 `draft`、`queued`、`dispatching`、`succeeded`、`failed`、`unknown`、`cancelled`、`expired` 和 `stale`。

领取只接受未过期的 `queued`，重新核验归属、消息版本、固定计划版本、已保存批准、配置及金额凭据，并从冻结快照重新计算指纹和金额。变更消息或不支持的计划版本会进入 `stale`，退回未派发预算。领取保存随机内部 `claim_id` 和 60 秒完成期限，COMMIT 成功后才返回冻结快照及配置；第二次领取或重连后的重复领取均拒绝。该凭据不能序列化给客户端。

完成必须匹配原 `claim_id`，只能更新尚未到期的 `dispatching`。仓储再次严格解码模型 JSON；缺字段、权限字段、其他工具、超过三步、重复/非法查询等结果失败，保留已派发尝试和金额。成功建议只保存有界查询，不授予检索权限。消息版本已经改变时不保存建议。

只有及时、有效建议和供应商适配器验证过的完整 usage 才能按冻结价格结算差额；没有可信 usage 时即使建议有效，也保留全部金额。失败、超时、未知结果和派发后取消全额保留。usage 越界保留全额并持久化停用配置；迟到的越界 usage 也停用配置，但不能改写已结算终态或重复退款。

取消与领取使用同一用户/对话锁：取消先提交则退回金额及未派发次数；领取先提交则保留整次预留和尝试，清除快照及建议，晚到结果不能恢复正文。取消终态返回原状态，不改写已有成功建议。

读取、列表、创建、批准、领取、完成及取消会处理所属对话的到期记录：过期草稿清除快照，过期 queued 退回尚未派发的额度，过期 dispatching 进入 unknown 并保留全部预留。读取因此会提交终态和结算，不是只读审计。没有自动扫描或供应商恢复，进程重启不能重新领取已经派发的请求；原批准重放也不会再次启动。

## 删除与运维兼容

删除对话在同一事务内结算未完成规划，退回 queued 预算、保留 dispatching 预算，然后立即删除快照、查询及请求记录。金额凭据和模型次数不随对话墓碑清理，删除/重建对话不能恢复已派发额度。用户删除时独立账本和凭据按原外键级联清除。

`reply-operations ledger` 继续核对整个共享金额账本；汇总现在包含两类凭据，分页明细新增 `request_kind`。`reply_status` 保留原字段名，模型规划凭据对应规划状态；对话被删除或墓碑清理后仍有金额凭据、类型及删除标记。审计不读取正文，不触发到期处理或模型调用。

## 验证

`TEST_DATABASE_URL=… make test-model-agent` 使用一次性数据库，覆盖真实事务预览/批准/领取/结算、精确确认与用户隔离、同键和重连查重、最后一份金额/次数竞争、配置不可变及停用、严格建议失败、缺失/越界用量、取消/领取竞争、到期和跨日退款、消息/计划版本/持久化批准复核、删除与独立凭据、共享回复账本、旧回复同键误退款防护，以及 deferred trigger 模拟 COMMIT 失败。

`make smoke` 自动运行全部 PostgreSQL 测试，并回归回复执行器、金额 HTTP/CLI、Redis、双代理入口及重启持久化。浏览器和真实模型未纳入本步。
