# 周期 RSS 后台运行

在[单次领取与执行器](rss-schedule-execution.md)之上，新增跨用户候选扫描、超时恢复批次和 scheduler RSS 循环。迁移 `0032_feed_schedule_scanning.sql` 增加活动授权及运行中请求扫描索引，不改变现有授权或开启执行。用户配置/预览/同意的 HTTP 与页面仍待接入；当前不会根据普通订阅自动生成周期授权。

## 显式启用

scheduler 同时满足以下配置才运行 RSS 循环：

```dotenv
SCHEDULER_MODE=local
RSS_SCHEDULES_ENABLED=true
RUN_FOREVER=1
```

`RSS_SCHEDULES_ENABLED` 默认 false，仅接受精确的 true/false；local 模式下非法值会在连接数据库前报错。`SCHEDULER_MODE=disabled` 始终关闭所有调度，不连接数据库，RSS 开关不能覆盖它。Compose 透传新开关，`.env.example` 保持关闭。先由 API/部署流程应用数据库迁移，再启动 scheduler；本地 Rust 进程需导出配置，不自动加载 `.env`。

该开关独立于 API 的手动采集开关。开启后仍必须有用户明确同意、未取消且在有效期内的周期授权才能联网。不会从现有订阅推断用户已同意周期采集，也不调用模型或抓取条目正文/附件。不要通过直接写 SQL 绕过用户授权；部署开关不是用户同意。

## 扫描与公平推进

内部 `FeedScheduleScanStore` 提供两种只读扫描，每页最多 20 项，游标由用户 UUID 和记录 UUID 组成：

- 到期扫描检查 active、授权未结束、已确认、当前时段落在十分钟派发窗口内，并排除已经持久化消费的时段。
- 恢复扫描仅选择时段映射关联的周期采集，且其 running 请求已经超过执行期限；授权已经取消或过期也能被恢复。不会自动恢复手动采集。

扫描结果只含内部用户/记录 ID，不是执行凭据，不对外提供跨用户接口。领取时仍按原事务重新核对用户、订阅、精确同意、时段唯一性、期限和共享额度；扫描与执行之间的状态变化不能绕过校验。

候选与恢复各自维护独立内存游标，一页内的额度不足、锁等待或其他单条故障不会阻止游标前进。到尾后从头开始，插入在游标之前的记录下轮可见。进程重启丢弃游标，但依靠数据库时段唯一性不重发。未领取的候选允许后续轮询重新检查，已消费时段永不补发；不保证所有授权都能在派发窗口内处理完，错过窗口继续跳过。

## 批次与进程生命周期

`FeedScheduleRunner` 每批先恢复最多 20 个超时周期请求，再处理最多 20 个候选。恢复只写 unknown，不退回额度、删除时段或重发；单条恢复及两类扫描分别有 5 秒等待上限。执行复用现有存储超时、8 秒传输上限和发送栅栏。

RSS 循环与原提醒/日报循环通过异步并发独立推进。每个成功批次结束后等待 2 秒，扫描失败时等待 5 秒，不因 RSS 网络等待而串行阻塞提醒/日报。仍共用数据库连接池和用户事务锁，并不保证外部资源故障完全隔离。一次性运行（`RUN_FOREVER` 非 1）各处理一个批次后退出，不自动清空所有候选。

日志只记录恢复数量、已返回终态的处理数量，以及跳过/未知数量；“completed”包含已保存的失败/unknown，不等于成功采集。扫描错误使用固定提示，不输出来源、正文、用户 ID 或连接串。SIGINT/SIGTERM 停止循环；已领取任务可能因进程退出留下 running，下一次启用后的恢复批次会在期限过后将其标记 unknown，不重新执行。

关闭 RSS 开关后不再扫描或自动恢复周期任务；原有显式采集状态核对与恢复仍可用于诊断。取消用户授权不能撤回已经通过发送复核的网络请求，迟到结果仍按既有规则丢弃。

## 验证

新增 PostgreSQL 测试覆盖跨用户多页扫描、单页上限、取消/未来/已消费时段排除，以及取消授权后仅恢复超时周期请求。进程测试验证默认关闭时不创建采集、批次先恢复 unknown 再处理未消费时段、重启不重复传输；成功采集使用受控传输夹具。真实进程启用接线在所有测试时段消费后验证，不向实际 RSS 服务发送请求。开关单元测试覆盖默认关闭、非法值和总开关优先级。
