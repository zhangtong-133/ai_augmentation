# v1 后续交付计划

目标是形成可日常使用的个人知识与学习闭环：采集/导入 → 私有知识积累 → 用户可解释地筛选信息 → 学习训练 → 有证据的能力反馈。模型分享和用量须逐次明确授权，失败可核对，用户删除内容后衍生副本不能残留。

目前基础知识库、规则日报、显式工具/Agent、训练记录、订阅连接和 RSS 评分执行已交付。下面按可独立验收的里程碑推进；不把夹具验收当作真实 Pro 账户可用性证明。

## 本轮：订阅评分阅读闭环

用户已有订阅，当前不依赖 API 额度。优先让已完成评分成为可阅读的结果；不为阅读新增模型请求，也不改变定时日报。

1. **交付与验收入口**：加入 `BROWSER_SPEC=feed-values.spec.mjs make browser-test`。只接受现存的单个 `.spec.mjs` 文件名，完整执行原有隔离数据库/HTTP 验收、再运行该文件的双入口浏览器测试，结束清理；未设置时仍为完整回归。每个新栈自行生成随机认证信息，不复用其他进程配置。
2. **私有阅读投影**：为已完成且仍有效的评分增加只读阅读接口。从原评分快照重建候选并校验完整评分，返回标题、摘要、原文链接、规则名次/分数和模型建议。ID 映射固定，同分按规则顺序、null 最后；不得混入后续采集内容。来源/偏好/连接变化造成原记录失效后不返回正文。不新增数据库副本或模型调用。
3. **阅读交互与整体交付**：在评分详情中显式读取结果，默认查看模型建议，可切回原规则排序；两种分数分别标注，null 不等于零。仅允许安全原文链接，文本按纯文本展示；核对、切换请求、退出、401 或失效时清除阅读内容。完成桌面/移动端、响应晚到与原有回归验收，更新文档并提交推送。

每步在验证通过后分别提交推送；实现状态和结果记录在路线图及对应设计中。

第一步已验收：非法文件名、路径穿越、缺失文件及未启用浏览器模式时均在访问 Docker 前拒绝；有效选择完成 162 个 PostgreSQL 测试、完整 HTTP smoke 和 10 个评分浏览器用例，测试栈已清理。

## 后续里程碑

| 顺序 | 交付内容 | 进入下一阶段的验收门槛 |
| --- | --- | --- |
| 4 | 基于训练证据的能力评估：先定义可追溯证据、评分量表、评估建议和用户确认，再实现仓储/API/页面 | 没有证据不给出能力提升；训练完成不能直接提高分数；删除证据使建议失效；用户隔离和版本冲突验收 |
| 5 | 模型交互流式展示与独立本地适配：先确定事件协议、取消语义与持久化边界，再接入运行时和页面 | 中途失败不伪装成功、不自动重发；退出取消读取，终态可恢复；本地协议通过夹具后再做用户选定模型实测 |
| 6 | 可选 API 评分路径：复用共享金额账本，完整计费上界、预留、一次发送和结算，再增加费用确认 UI | 与订阅凭据隔离；并发不能超预算；未知用量保留占用；默认关闭，不依赖用户已有 API 额度 |
| 7 | v1 集成交付与实用性验收：部署说明、备份恢复、运维诊断、数据生命周期和完整回归 | 端到端走通信息筛选到学习反馈；CI 通过；配置型跳过项明确；真实订阅/公网/本地模型实测单独记录，不凭测试夹具宣布通过 |

真实模型实测应由用户显式选择连接、审阅分享内容并确认用量；此开发计划不代表授权使用个人凭据或消耗订阅额度。API 金额路径和全局残留向量后台回收不能阻塞无 API 额度的订阅阅读流程。

第二步已验收：[私有阅读接口](rss-value-reading.md)及纯投影、用户隔离/失效测试已完成；Rust/前端检查和完整 HTTP smoke 通过，无迁移或额外模型请求。

第三步已验收：[评分阅读视图](rss-value-reading.md)完成模型/规则顺序切换、摘要/安全原文、快照校验及跨面板/跨账户失效保护。前端检查、18 个定向用例、完整 HTTP/数据库验收与 138 个浏览器用例通过；8 个可选索引/公网用例按配置跳过。三个本轮步骤均已完成；后续从里程碑 4 的训练证据与评估协议开始，真实模型实测仍单独记录。

## 里程碑 4 分步交付

本轮先完成[证据协议](learning-evidence.md)、随计划返回的只读证据检查、任务内的量表回看交互。检查仅标注材料缺口，非空备注仍待人工核验，不输出能力分数。持久化评估建议、证据级删除和带版本确认仍是后续步骤，不能将本轮标为能力评估全部完成。

里程碑 4 的本轮三步已完成：协议、只读检查接口、任务内核验提示与原始记录回看。Rust/前端检查、162 个 PostgreSQL 测试、完整核心 HTTP smoke 和 10 个学习页面双入口浏览器用例通过。没有调用模型或增加迁移；下一批从结构化证据保存及删除、持久化评估建议、带版本与幂等保障的用户确认开始。

里程碑 4 下一批按“结构化证据仓储 → 会话/CSRF 接口与生命周期验收 → 页面保存、回看、删除和失败恢复”交付。新增 0036 迁移，材料仍不推断分数；后续再推进持久化评估建议及显式确认。

结构化证据批次已完成：0036 仓储迁移、保存/删除接口和页面均已交付；删除正文留墓碑防止恢复，来源删除级联清理，四项材料始终待核验。Rust、前端、162 个 PostgreSQL 用例、5 个学习 HTTP 用例、核心 smoke 和 14 个双入口浏览器用例通过。下一批从证据引用绑定的持久化评估建议及版本确认开始；不把证据齐全视为能力提升。

核验确认批次按“量表与核验仓储 → 原子确认和来源撤销 → 页面二次确认”推进。采用用户逐项核验，分数必须主动填写；模型自动评估建议仍独立待办。协议与迁移见[核验确认设计](learning-review-confirmation.md)。
