# v1 后续交付计划

目标是形成可日常使用的个人知识与学习闭环：采集/导入 → 私有知识积累 → 用户可解释地筛选信息 → 学习训练 → 有证据的能力反馈。模型分享和用量须逐次明确授权，失败可核对，用户删除内容后衍生副本不能残留。

目前基础知识库、规则日报、显式工具/Agent、训练记录、订阅连接和 RSS 评分执行已交付。下面按可独立验收的里程碑推进；不把夹具验收当作真实 Pro 账户可用性证明。

## 已交付：订阅评分阅读闭环

用户已有订阅，当前不依赖 API 额度。优先让已完成评分成为可阅读的结果；不为阅读新增模型请求，也不改变定时日报。

1. **交付与验收入口**：加入 `BROWSER_SPEC=feed-values.spec.mjs make browser-test`。只接受现存的单个 `.spec.mjs` 文件名，完整执行原有隔离数据库/HTTP 验收、再运行该文件的双入口浏览器测试，结束清理；未设置时仍为完整回归。每个新栈自行生成随机认证信息，不复用其他进程配置。
2. **私有阅读投影**：为已完成且仍有效的评分增加只读阅读接口。从原评分快照重建候选并校验完整评分，返回标题、摘要、原文链接、规则名次/分数和模型建议。ID 映射固定，同分按规则顺序、null 最后；不得混入后续采集内容。来源/偏好/连接变化造成原记录失效后不返回正文。不新增数据库副本或模型调用。
3. **阅读交互与整体交付**：在评分详情中显式读取结果，默认查看模型建议，可切回原规则排序；两种分数分别标注，null 不等于零。仅允许安全原文链接，文本按纯文本展示；核对、切换请求、退出、401 或失效时清除阅读内容。完成桌面/移动端、响应晚到与原有回归验收，更新文档并提交推送。

每步在验证通过后分别提交推送；实现状态和结果记录在路线图及对应设计中。

第一步已验收：非法文件名、路径穿越、缺失文件及未启用浏览器模式时均在访问 Docker 前拒绝；有效选择完成 162 个 PostgreSQL 测试、完整 HTTP smoke 和 10 个评分浏览器用例，测试栈已清理。
