# Sprint 2：历史原文迁移与孤立对象清理

## 入口与安全前提

新增管理员离线命令 `object-maintenance`，复用 API 的 `DATABASE_URL`、`OBJECT_STORE_ENABLED=true` 及 `OBJECT_STORE_*` 配置。配置需导出到进程环境；不会自动加载 `.env`，不经过用户 HTTP 接口，也不新增定时删除任务。默认只预览，只有 `--apply` 才上传/删除对象和切换文档引用。本轮不新增数据库迁移。

```sh
# 预览前 100 个内联文档；只输出数量，不输出原文或凭据
cargo run -p api-server --bin object-maintenance -- migrate
# 执行一批；完成后重新运行，直到 eligible=0（并发迁移时待其他执行器结束后复核）
cargo run -p api-server --bin object-maintenance -- migrate --apply

# 预览一页对象；使用返回的 next_cursor 作为下一页的 --after 参数
cargo run -p api-server --bin object-maintenance -- gc
# 确认以下安全条件后，显式执行该页清理
cargo run -p api-server --bin object-maintenance -- gc --apply --exclusive-bucket
```

执行清理前必须确认：

- 桶由当前这一个数据库独占，不能共享给其他部署、恢复库或其他应用。键名检查不能判断另一个数据库的引用。
- 所有 API/迁移写入进程均升级到本版本，旧版写入器和手工改引用流程必须停止；共享锁不能保护未遵循协议的写入器。
- 数据库与对象存储时钟正常；备份/恢复策略允许删除这些无当前引用且超过 24 小时的对象。需要支持恢复旧数据库快照时，应保留相应对象备份，或不要运行清理。
- 使用主数据库，不使用可能延迟的只读副本；维护凭据包含所需的 List/Get/Put/Delete 权限。

`--exclusive-bucket` 是管理员对部署边界的显式确认，程序无法自动验证桶是否被其他系统共享。未启用对象存储、参数错误、连接失败等情况退出非零。维护输出含对象键游标，仅面向管理员，不应公开。

## 迁移协议

按文档 UUID 选择最多 100 个 `original_object_key IS NULL` 的旧记录。每个文档在独立事务中领取行锁（`SKIP LOCKED`），读取同一锁定行的原文，使用新的随机键上传到私有桶。三种格式复用现有格式/大小校验及 content-type：Markdown 保留 UTF-8 原字节，PDF 保留二进制，网页保留已解码 HTML。

上传后 GET 回读进行字节级比较；成功才将数据库引用切换到对象并清空 PDF/HTML 内联字段。Markdown 的文本列继续保留以兼容现有结构；文本分块、摘要、标题、创建时间、索引任务和文档 ID 不变。读请求只可能看到提交前或提交后的完整记录。

上传失败、回读失败/不一致、事务失败或进程中断时不会主动删除候选对象：数据库回执丢失可能意味着已提交。重跑跳过已迁移记录，未提交记录仍可重试。可能留下的对象由后续 GC 在保留期后处理。批次中途失败不撤销之前已提交的文档，命令可安全重跑；并发执行不要求额外连接读取锁定行，避免连接池耗尽。

## 清理协议

S3 普通桶按键名升序列举 `users/` 下的一页对象，最多 100 个，`--after` 为排他的对象键游标。重复运行直到返回 `next_cursor=null`；预览游标和执行游标应分别遍历，不能从预览末尾直接开始删除，否则会跳过已预览的页。列举期间新出现且排在游标之前的对象在下一轮从空游标扫描时处理。

只接受 `users/{标准UUID}/documents/{标准UUID}/{标准UUID}` 这一精确格式，不处理桶内其他文件、备份或任意前缀。对象最后修改时间至少早于数据库当前时间 24 小时，且数据库不存在任何文档引用，才成为候选。

所有新外部导入和迁移从上传前至数据库提交期间持有相同的 PostgreSQL 事务级共享 advisory lock。清理在每个候选的数据库核对前获取排他锁，并持有到删除完成，确保进行中的上传/提交不会被误认为无引用对象。忙碌时不等待写入器而是明确报错，稍后重跑该页；新写入器等待清理最多 5 秒，锁超时返回存储错误，可重试导入。每次只锁一个对象的检查/删除过程，不跨整页持锁。

删除前再 HEAD 校验修改时间与列举结果一致、仍超过保留期；数据库错误、HEAD 错误、删除错误均停止本次命令，不绕过保护。已不存在的对象视为幂等成功/跳过。删除用户导致的失去引用对象也使用相同路径处理。对象删除不是数据库事务的一部分，后续失败不恢复已删除对象；若桶未启用版本/备份，删除不可恢复。S3 版本桶的历史版本、未完成 multipart、向量残留清理不在本轮范围。

实际删除拒绝处于恢复模式的 PostgreSQL 或只读事务，并显式使用 READ COMMITTED，确保获取锁后的引用核对使用新快照。S3 列举与 HEAD 时间统一为秒精度，并额外保留一秒，避免时间精度差异导致提前清理或永远跳过。

## 验证边界

`make smoke-objects` 使用专用 PostgreSQL/MinIO，验证三种格式的迁移与回读一致性、预览无上传、并发迁移、重复执行、上传失败和回读损坏不切换引用、近期对象保留、共享锁冲突、HEAD 时间变化保护、删除失败可重试、引用保护、用户删除后的回收、非项目键保留和超过 100 个对象的游标分页。年龄在夹具内模拟，不通过等待两天或修改真实桶对象时间实现；实际上传、列举、HEAD、读取、删除均使用真实 MinIO。

此命令没有在用户现有文档或真实桶上执行；测试只删除隔离测试资源。历史数据的实际迁移/清理需要管理员另行决定执行时机。
