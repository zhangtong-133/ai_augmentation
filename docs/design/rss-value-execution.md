# RSS 订阅评分内部执行

在[评分授权仓储](rss-value-reviews.md)之上新增 `FeedValueExecutionStore` 和内部 `execute_subscription_value`，只领取已批准的订阅模式。迁移 `0035_feed_value_execution.sql` 增加一次领取标识、发送时间、执行期限和校验后的评分。API 模式仍不能执行；本次不涉及金额预留或供应商回退。

## 单次派发和竞争

领取在用户行锁内再次核对连接、期限、完整候选和偏好快照，把 authorized 原子变为 running，生成不可复用的随机领取标识。最多执行 90 秒且不超过原同意期限；多个执行器并发领取只有一个成功。领取响应丢失或进程退出也不会恢复领取权限。

执行器先让可信本地运行时验证当前权限和模型可用性（最多 10 秒），随后用返回的已验证连接证据进入发送检查。仓储匹配主机、client、subject 摘要、模型、连接版本及期限，并核对领取快照未被改写。发送标记和 sending 审计共用事务，发送标记不能重置；只有该事务成功返回 true 才允许调用运行时。实际模型请求最多等待 60 秒，不重试。

发送标记事务是撤销竞争的线性化点。取消或连接撤销先完成则不允许发送；发送先取得许可，则取消不能保证阻止已经获准的外部请求或退还订阅用量，但晚到结果会被丢弃。来源、条目、偏好、连接变更同样作废运行中的计划。网络调用期间不持有数据库事务。

## 结果与恢复

仓储重新从冻结快照构造协议，严格校验完整候选 ID、分数、理由和输出大小；显式 null 是合法的放弃评分。只有已记录发送且仍有效的运行才可变为 succeeded。结果只是模型建议，不覆盖规则评分、不改日报、不触发工具或其他调用。

验证失败、调用失败、超时或异常输出进入 unknown，清除候选及输出，不保留供应商原始错误。存储故障返回错误并保留已提交的领取/发送状态；之后读取、列表或再次领取会按期限把遗留 running 回收为 unknown，不重新派发。失败事务不产生半条审计或半个状态；完成写回可在同一领取标识下幂等核对，不能重新调用模型。

取消会清除运行中的候选；来源/偏好/连接变更也会清除已完成的候选和评分，避免删除源内容后留下评分副本。用户删除级联清除记录。审计只保留状态和时间，领取标识、主机/账号证据及令牌不进入用户返回对象。

## 当前接入边界

`SubscriptionValueRuntime` 是内部可信端口，本轮由确定性夹具验收。生产适配器仍需绑定同一份锁定的本地账号/凭据，在验证与发送之间禁止切换身份，并适配现有 ChatGPT 流式调用。不能把 API 请求中的 temperature、max_output_tokens 当作订阅传输支持的参数，也不能把本地超时或字节上限宣称为供应商订阅用量硬上限。

本轮没有新增 HTTP、评分授权页面、后台扫描或本地评分命令，不会自动读取凭据或调用用户模型。真实 Pro 账户未验证。下一步接入本地运行时和显式发起入口，再实现用户评分授权/结果页面；API 模式需独立接入金额预留。

## 验收

真实 PostgreSQL 用例覆盖并发单次领取、拒绝 API/跨用户请求、错误身份/过期证据/篡改快照拒绝、单次发送标记、完整结果持久化、进程重连、未知结果和期限回收、取消与撤销栅栏、来源删除清理、领取/发送/完成审计失败原子回滚，以及验证中和发送中的取消竞争。复用既有评分协议测试覆盖异常模型输出。

执行 `make check`、前端 lint/typecheck/build 和完整 `make smoke`。本轮无页面改动，不重跑 Playwright；对象存储/向量专项及真实模型调用不属于本轮验收范围。

本轮验收结果：Rust 1.99 全量检查、前端三项检查及完整 smoke 通过；162 项 PostgreSQL 测试通过（新增 7 项执行验收），生产 API 使用 Rust 1.96 构建通过，双网关和重启恢复验收通过。一次性测试容器、网络及数据已清理。
